# 제4장 작업 위임: 메시지, 첨부 파일 그리고 성공적인 인수인계

요구사항을 너무 간단하게 전달하면, 무관한 웹페이지 수십 개를 검색하거나 파일을 엉망으로 수정하기 쉽습니다. **메시지를 보내는 것은 클라우드 컴퓨터에 업무를 인수인계하는 것입니다**.

- **작업 경계를 명확히 제한**하고 첨부 파일의 용도를 설명하여 자의적인 판단을 방지하세요
- 명확한 지침을 제공하여 즉시 검수 가능한 결과물을 받아보세요
- 실행 중 언제든지 끼어들어 방향을 바로잡거나, 음성으로 배경 정보를 보충하세요

![작업 위임: 메시지, 첨부 파일 그리고 성공적인 인수인계](/info/04-handoff.png)

## 좋은 요청의 5가지 요소

![좋은 요청의 5가지 요소](/info/04-handoff-s1.png)

Grok Bot에게 작업을 전달할 때는 **지시사항에 목표와 도구 범위를 명확히 명시해야 합니다**. 세부 규정은 [《Grok Bot》](https://cursor.com/cn/docs/grok-bot) 문서를 참조하세요.

1. **동작은 구체적이고 단일하게**. "연구 좀 해봐" 대신 "스크랩 및 대조" 또는 "외부 발송 메일 초안 작성"과 같이 명시하세요. 경로가 짧을수록 단계가 절약됩니다.
2. **데이터 출처 한정**. 전체 웹을 무분별하게 검색하지 않도록 Notion 페이지, Slack #sales-leads 채널 또는 특정 URL을 지정하세요.
3. **승인 기준선(Red Line) 명확화**. 읽기 및 대조는 자동으로 실행하되, **외부 메일 발송, 온라인 결제 또는 데이터 수정/삭제가 수반되는 경우 반드시 일시 중지하고 승인을 대기하도록 하세요**.
4. **결과물 형태 고정**. **구두 보고를 지양**하고, `/workspace/leads/`에 링크가 포함된 Markdown 보고서 또는 CSV 스프레드시트를 생성하도록 요구하세요.
5. **오류 처리 규칙 및 사실 범위 정의**. 추측과 객관적 사실을 구분하고, 로그인 세션 만료 시 건너뛰고 기록하도록 하며, **무한 루프 재시도를 금지하세요**.

## 첨부 파일 사양 및 제한 사항 목록

업로드 규칙은 [《使用 Grok Bot》](https://cursor.com/cn/docs/grok-bot/work)을 참조하세요.

### 사양 제한

- 데스크톱 앱에서는 메시지당 **최대 6개**로 제한됩니다(초과분은 워크스페이스에 보관). 이미지/문서/오디오는 최대 25MB, 동영상은 최대 200MB까지 지원됩니다.
- 문제가 발생하거나 오류가 나면, 로컬에서 PDF, CSV 또는 이미지로 먼저 변환한 후 업로드하세요.

### 인수인계 및 그룹 채팅

1. **파일을 끌어다 놓은 뒤 바로 Enter를 누르지 마세요**. 각 파일의 정체, 상호 연관 로직, 보호 지침을 명확히 작성하세요.

```text
上傳的 PDF 是已經簽署的標準採購合同樣板。上傳的 Excel 是本月供應商提交的實際報價清單。
請對照合同樣板中第 4 條關於各類物料的基準單價，逐行核驗 Excel 裡的實際報價。
標出單價超出基準價的所有條目，在附帶的備忘中引用合同中的對應條款編號。
將核驗結果另存為一份新的 Excel 表格，並輸出一份簡短的例外摘要。
請勿改動原始上傳文件。
```

2. 그룹 채팅에서 Bot 간의 통신은 **순수 텍스트만 지원**됩니다. 다운스트림 Bot이 첨부 파일을 확인해야 한다면 1:1 채팅으로 직접 전달해야 합니다.

## 작업 위임 실전 프롬프트 라이브러리

자주 쓰는 시나리오에는 **템플릿을 바로 적용**하여 약간만 수정해 사용하세요.

1. **리서치 및 아웃리치**: 리드 조사 및 자료 준비, 직접 발송하지 않음.
```text
從我們的 CRM 系統中獲取本週銷售管道的重點評審列表。
請跳過當前已經處於活躍跟進序列中的聯繫人。
在指定公開網頁和已授權的 Slack 相關頻道中，深入調研排名前五的重點帳戶，找出負責採購或技術的對口聯繫人。
參考我在系統中歷史郵件的口吻，為這五位聯繫人分別起草個性化的初次外聯郵件。
將草稿保存在系統草稿箱中，並在明天上午 9 點前在此對話中列出清單供我審批。未經我的明確確認，絕不向外發送任何郵件。
```
2. **첨부 파일 검증**: 다중 시트 대조 및 수입/지출 검증.
```text
附件中的 PDF 為《2026 年度差旅與報銷政策細則》，CSV 表格為本月部門提交的待審批費用報銷流水。
請逐項核對 CSV 中的每一筆申報項目：
1. 檢查報銷金額是否超過對應城市級別的住宿與餐飲標準。
2. 檢查單筆超過 500 元的支出是否有對應的發票類別標記。
3. 提取所有不符合政策規定的例外申報，列明行號、申報人、金額、超標原因及違背的政策條款。
最後生成一份 Markdown 格式的核查報告，並列出通過與未通過的統計彙總。保持原始 CSV 文件不被改動。
```
3. **웹사이트 점검**: 페이지 순회 점검 및 증적 보관.
::: details 작업 위임 실전 프롬프트 라이브러리
```text
你負責檢查我的網站執行狀態。本次只訪問我提供的以下三個頁面：首頁、最新更新記錄頁、使用者註冊頁。
逐一核驗各頁面是否能正常打開、關鍵按鈕是否回應、文本資訊是否存在斷鏈或明顯過期內容。
排查過程中必須執行以下要求：
1. 發現任何顯示例外或報錯時，保存完整的頁面 URL、檢查時間戳記以及當時的螢幕截圖。
2. 區分頁面直接看到的事實與你的推測，事實寫在證據欄，分析寫在備註欄。
3. 檢查受阻或遇到需要驗證碼時，記錄阻礙原因並繼續檢查下一個頁面，不要重複嘗試。
4. 檢查結果報告保存在 /workspace/site-check/ 目錄下，命名為 check-report.md。
你僅有隻讀檢查與生成報告的權限，嚴禁更改後台設定或提交任何表單。
```
:::
4. **계획 검토**: 복잡한 작업 수행 전 로직을 검토하여 이탈 방지.
::: details 작업 위임 실전 프롬프트 라이브러리
```text
我準備讓你整理過去一個季度跨 Notion、Gmail 和 GitHub 的客戶產品缺陷回饋。
在正式開始執行資料讀取與整理之前，請先不要呼叫任何批量工具，先在對話中向我提交一份執行計劃：
1. 列出你準備按順序訪問的系統、模組與具體檢索詞。
2. 說明你打算提取哪些關鍵欄位，以及如何去重。
3. 標明整個流程中哪些環節可能涉及對外部狀態的更改。
4. 說明你打算將階段性文件保存在雲端電腦的哪個路徑，以及遇到權限不足時如何處理。
我確認並批准你的計劃後，你再開始執行。
```
:::
5. **수신 메일 알림**: 핵심 요약 및 분류 전달.
::: details 작업 위임 실전 프롬프트 라이브러리
```text
使用已連線的郵箱外掛，讀取收件箱過去 24 小時內收到的全部新郵件。
按照以下業務邏輯進行分類處理：
1. 屬於系統續費、訂閱扣款帳單的郵件，提取服務商、扣款金額與下次續費時間。
2. 屬於使用者直接提問或回饋 Bug 的郵件，提取發件人郵箱、問題概括與緊急程度。
3. 屬於行銷推廣、垃圾資訊的郵件，直接歸入忽略清單。
在當前會話中輸出一份分欄概覽：僅展示需我關注的帳單與緊急回饋，並在每條記錄後附帶郵件主題與時間。
所有郵件保持未讀或已讀原狀，未經審批嚴禁歸檔、刪除或起草回覆。
```
:::

## 장기 규칙과 단일 작업: 가훈을 집안일과 혼동하지 마세요

![장기 규칙과 단일 작업: 가훈을 집안일과 혼동하지 마세요](/info/04-handoff-s4.png)

**장기 규칙과 단일 작업을 명확히 구분하세요**([《使用 Grok Bot》](https://cursor.com/cn/docs/grok-bot/work) 참조). 임시 파라미터를 장기 설정에 넣지 말고, 매번 기본 원칙을 다시 지시하지도 마세요.

| 유형 | 주기 및 설정 | 예시 및 제한 |
| --- | --- | --- |
| 장기 규칙 | 세션을 넘어 적용됨; Bot Details 설정 또는 "이 내용을 장기 규칙으로 기억 영역에 저장해 줘"라고 입력 | 권한 기준선, 날짜 YYYY-MM-DD |
| 단일 작업 | 단일 턴에서만 유효하며 누적되지 않음; 직접 지시 | 12개 계정 또는 3개 오디오 처리, 10시 회의 체크리스트 추출 |

모든 Bot은 `/workspace`를 공유합니다([《10 條必備經驗，讓你的 Grok Bot 變得更好用》](https://jcng5q8n0f3z.feishu.cn/wiki/Hfqxwy3zQiWkRPkVjRZcVCuHnbc) 참조).

**기억은 비즈니스 시스템을 대체할 수 없습니다**. 잔액이나 재고는 반드시 원천 데이터에서 조회해야 하며, 임의로 추측해 지어내는 것은 엄격히 금지됩니다.

## 작업 진행 중 개입: 중지, 끼어들기 및 승인

![任務進行時的干預：停止、插話與審批](/info/04-handoff-s5.png)

### 끼어들기 및 중지
Bot이 목표에서 벗어났을 때는 일반 메시지를 보내 **즉시 끼어들기**가 가능합니다. 예를 들어 "2026년 10월 업데이트된 신규 규격으로 변경해서 다시 조회해 줘"라고 보낼 수 있습니다.

작업 중 오류가 발생하거나 고위험 호출이 발생하면 입력창에 다음 네 글자를 보내 중지시키세요.
```text
立即停止
```

**중지는 아직 실행되지 않은 동작만 차단하며, 이미 저장된 파일이나 전송된 API 요청은 절대 롤백되지 않습니다**. 중지한 후에는 다음 3단계로 점검하세요.
1. 클라우드 컴퓨터 미리보기 패널을 열어 상태를 확인합니다.
2. 중간 생성물이나 잘못 기록된 내용을 정리합니다.
3. 범위를 좁히고 경계를 명확히 한 후 다시 시작합니다.

### 승인 및 시간 초과
Auto-review를 활성화하거나 고위험 작업이 트리거되면 '작업 검토' 카드가 팝업됩니다([《Grok Bot 操作指南》](https://cursor.com/cn/help/grok-bot/how-to) 참조). 여기에는 세 가지 옵션이 포함됩니다.
- 允許一次(한 번 허용): 이번만 승인하며, 이후 동일한 작업 시 다시 확인합니다.
- 始終允許(항상 허용): 화이트리스트에 추가하고 다시 묻지 않습니다.
- 拒絕(거부): 해당 작업을 완전히 차단합니다.

| 시나리오 | 대기 방식 | 시간 초과 결과 |
| --- | --- | --- |
| 실시간 상호작용 | 일시 중단 대기 | 클릭하여 처리할 때까지 지속 대기 |
| 백그라운드 무인 실행 | 약 10분 후 자동 만료(Expired) | **작업을 실행하지 않고 태스크 종료** |

### 자격 증명 제어권 인수(Action needed)
비밀번호, 2FA 및 CAPTCHA나 실제 결제가 수반될 때 제어권 인수 카드가 팝업되며, 다음 3단계로 진행합니다.
1. **Take over**를 클릭하여 클라우드 컴퓨터에서 수동으로 입력합니다.
2. 완료 후 **I'm done**을 클릭하여 제어권을 반환합니다.
3. **일반 대화창에 절대 평문 비밀번호를 입력하지 마세요**.

## 음성 상호작용: 실시간 음성 통화와 음성 받아쓰기의 구분 사용

Grok Bot에는 받아쓰기와 음성 통화라는 **서로 다른 두 가지 음성 기능**이 포함되어 있습니다. 자세한 내용은 [《與 Bot 語音聊天》](https://cursor.com/cn/help/grok-bot/voice-chat) 및 [《Grok Bot 操作指南》](https://cursor.com/cn/help/grok-bot/how-to)을 참조하세요.

### 두 가지 모드 비교

| 모드 | 트리거 및 단축키 | 출력 및 활용 시나리오 |
| --- | --- | --- |
| 음성 입력(받아쓰기) | 데스크톱에서 '음성 입력 시작' 클릭, Mac은 Cmd+D, Win/Linux는 Ctrl+D, 모바일은 '받아쓰기 시작' 탭 | 텍스트가 입력창에 채워짐, 프롬프트 정밀 수정이나 파라미터 보충에 적합 |
| 실시간 음성 채팅 | **입력창을 비운** 후 파형 아이콘(Start voice chat) 클릭 | 양방향 실시간 통화, 생각 정리나 빠른 업무 인수인계에 적합 |

### 시작 단계 및 주의 사항

1. 개별 Bot 대화창을 엽니다.
2. **입력창을 완전히 비워야 합니다**. 공백이나 임시 저장된 초안이 남아 있으면 파형 아이콘이 숨겨집니다.
3. 파형 아이콘을 클릭합니다. 최초 사용 시 마이크 권한을 허용해야 합니다.
4. Connecting…(모바일에서는 Calling…)이 표시되며, Bot이 먼저 말을 시작하면 연결된 것입니다.

### 제어 및 필수 제한 사항

- 통화 중 음소거, 스크롤 자막 확인, 음성 속도 및 음색 조절이 가능합니다. 다른 화면으로 전환하여 자료를 볼 때는 상단 표시줄의 '음성 채팅으로 돌아가기'를 클릭하여 복귀할 수 있습니다.
- **1:1 개별 채팅만 지원**되며, 그룹 채팅, 멀티 Bot 그룹 및 '팀 Bot'에서는 시작할 수 없습니다.
- **동시에 하나의 통화만 유지할 수 있으며**, 새로운 Bot으로 전환하려면 '종료 후 채팅'을 확인해야 합니다.
- 통화 종료 후 총 통화 시간을 기록하는 Voice chat 카드가 자동으로 생성되며, 클릭하여 전체 텍스트를 확인할 수 있고, 후속 작업은 텍스트 대화에서 계속 진행할 수 있습니다.

## 흔한 실패 패턴과 최적화 비교

1. **경로 수렴**: 범위와 방법을 정하지 않으면 Bot이 콘솔을 무분별하게 클릭하고, **심지어 프로덕션 환경의 코드까지 수정할 수 있습니다**.
```text
  幫我維護一下網站，看看有沒有什麼 Bug。
  ```
페이지와 점검 단계를 제한하는 방식으로 변경:
```text
  對站點清單（/workspace/sites.txt）中的三個靜態展示頁進行巡檢。
  用雲端瀏覽器打開每個頁面，檢查主控台是否有 404 或 500 報錯，檢查頂部導覽欄連結是否全部有效。
  將報錯資訊、對應頁面 URL 及當時的螢幕截圖寫入 /workspace/logs/err-20261014.md。
  全程僅做唯讀檢查，嚴禁點選任何帶有提交或刪除性質的表單按鈕。
  ```

2. **승인 경계**: 외부 발송 권한을 함부로 주지 마세요. 의도를 잘못 파악하면 **중요 고객에게 잘못된 내용을 발송하기 쉽습니다**.
```text
  讀取 Gmail 裡的未讀郵件，重要的直接幫我回一下。
  ```
핵심 단계는 사람이 직접 승인하도록 변경:
```text
  讀取 Gmail 中過去 12 小時的未讀郵件。
  僅篩選出發件人屬於我們現有企業客戶、且正文包含售後或諮詢訴求的郵件。
  根據產品常見問題手冊，為每封郵件起草回覆草稿並存入 Gmail 草稿箱。
  在當前對話中列出客戶名稱、郵件摘要與草稿正文，等待我的審批。未經我的明確確認，絕不點選發送。
  ```

3. **사실 분리**: 프롬프트에 편향을 담지 마세요. **Bot이 가설에 끼워 맞춰 사소한 프로모션을 가격 전쟁으로 오판하는 것을 방지해야 합니다**.
```text
  去看看競品今天的動態，總結一下他們是不是要跟我們打價格戰。
  ```
객관적인 데이터와 추측을 분리:
```text
  訪問競品官網的公開定價頁與首頁橫幅，獲取他們當下的方案價格表。
  對照我們在 /workspace/competitor/last-month-price.json 中記錄的舊價格：
  1. 事實列：標出哪些 SKU 的標價發生了變動，變動金額是多少，附帶頁面截圖與訪問時間。
  2. 推測列：基於該降價是限時促銷還是永久調價，給出你的分析理由。
  兩部分內容必須分開分欄呈現，不得將分析推論當作已知事實。
  ```

4. **읽기 전용 보호**: 마스터/서브 테이블과 보존할 필드를 지정하지 않으면 **원본 데이터가 덮어씌워져 손상되기 쉽습니다**.
```text
  （直接拖入三個 Excel 表格）把這幾個表整理一下。
  ```
어느 테이블을 기준으로 할지 명시하고 읽기 전용으로 설정:
```text
  上傳的三個表格分別是 7 月、8 月和 9 月的銷售明細。
  以「訂單編號」為唯一主鍵進行資料去重合並：
  1. 欄位統一保留：訂單號、成交日期、客戶名稱、銷售代表、成交金額。
  2. 生成一份全新的 Q3_sales_summary.csv 文件，保存在當前工作區。
  3. 保持我上傳的原始 7、8、9 月表格內容與檔名完全不變。
  ```

5. **단일 사명**: 하나의 Bot에 여러 작업을 몰아넣지 마세요. 기억이 꼬일 뿐만 아니라 **주간 사용량 한도를 빠르게 소진하게 됩니다**.
```text
  你幫我寫一篇關於新產品的推文，順便把昨天的帳目算了，然後再幫我看看競品推特。
  ```
단일 작업으로 나누어 역할을 분담:
```text
  遵循一個 Bot 負責一項核心任務的原則。當前 Bot 僅承擔社媒文案起草職責：
  依據 /workspace/product/spec.md 中的新功能說明，為 X 平台起草三條不同風格的發表文案。
  要求突出效能提升資料，字數控制在 280 字元以內。
  帳目核算與競品調研交由對應的專用 Bot 負責，不要在此會話中處理。
  ```

## 실제 비즈니스 인수인계 사례

### 웹사이트 일상 점검 및 증적 보관
웹마스터 yishan은 점검 요구사항을 검수 사양서 형태로 직접 작성했습니다. 작업 디렉터리를 `/workspace/site-check/`로 엄격히 한정하고 홈, 최신 글, 구독 진입 페이지만 점검하도록 허용했으며, 무분별한 크롤링 탐색은 엄격히 금지했습니다.
- 보고서에는 완전한 URL, 타임스탬프, 당시의 스크린샷을 반드시 남겨야 합니다. **직접 목격한 오류는 사실로 분류하고 원인 분석은 추측으로 분류하여 반드시 구분해 기록해야 합니다.**
- 로그인 만료나 깨진 링크가 발생하면 누락 사항을 기록하고 즉시 건너뛰어야 하며, 반복해서 매달리는 것을 엄격히 금지했습니다. 구체적인 방법은 [《如何在一個小時內深入使用 Grok Bot》](https://jcng5q8n0f3z.feishu.cn/wiki/GBV8wdZOaijukikjO0pcYFWKnbg)을 참조하세요.

### 수신함 중계 및 업무 분류 전달
一澤Eze는 Gmail을 전담할 수신함 전용 Bot을 별도로 구성하고, 다운스트림의 개별 Bot들에게는 이메일 접근 권한을 각각 열어주지 않았습니다.
- 피드백 이메일을 받으면 1:1 채팅으로 '제품 피드백 Bot'에 전달하고, 청구서는 '구독 관리 Bot'에 전달합니다.
- 순수 수치 비교는 명령줄 스크립트에 바로 맡겨 실행합니다. **Bot에는 증분 데이터만 동기화하여 주간 사용량 한도를 절약할 수 있습니다.**
- 고권한 도구를 아무 데나 연결하지 말고, 전담 창구를 두어 1차 필터링을 거치는 것이 가장 안전합니다.

  노하우 정리는 [《10 條必備經驗，讓你的 Grok Bot 變得更好用》](https://jcng5q8n0f3z.feishu.cn/wiki/Hfqxwy3zQiWkRPkVjRZcVCuHnbc)을 참조하세요.

### 비서실장 사전 조사 및 Bot 구축
CyrilXBT는 먼저 비서실장 Bot에게 팀의 Notion과 Slack을 읽게 하여, 가장 시간이 오래 걸리고 반복성이 높으며 병목이 잦은 상위 3개 업무를 도출한 뒤 3단계로 진행했습니다.
1. 비서실장 Bot을 수동으로 실행하며 사람이 옆에서 출력 품질을 감독합니다.
2. 문제가 없음을 확인한 후 스킬로 자산화하고, 독립된 전용 Bot을 구축합니다.
3. 마지막으로 정기적인 자동 실행을 구성합니다.
**발송, 구매, 배포 또는 온라인 시스템 수정이 수반되는 노드는 반드시 엄격하게 사람의 수동 승인을 유지해야 합니다.

** 전체 튜토리얼은 [《How to master Grok Bot in 16 minutes - Full Course｜CyrilXBT》](https://jcng5q8n0f3z.feishu.cn/wiki/WGaCwZU71iHAGPkzjkLcahN2nHd)를 참조하세요.

## 주의해야 할 함정

1. **첨부 파일 업로드 시 설명 추가**: 여러 장의 이미지나 2개 이상의 표를 전달할 때는 **반드시 용도를 명시**해야 합니다. 그렇지 않으면 주/부 관계가 뒤바뀌기 쉽습니다.
2. **장기 규칙은 기억(Memory)에 저장**: 단일 지시는 세션이 바뀌면 사라지므로, 기본 원칙은 **Bot 세부 정보의 About/역할에 작성**하거나 기억에 저장하세요.
3. **로컬 연동 시 절전 방지**: 순수 클라우드 환경은 노트북을 덮어도 실행되지만, 로컬 컴퓨터와 연동된 경우 절전 모드로 들어가면 연결이 끊기므로 **전원 및 절전 설정을 꼭 확인**하세요.
4. **Bot 간 이미지 전달은 경로 활용**: 그룹 내 Bot 간 통신은 순수 텍스트만 지원하므로, 이미지를 전달할 때는 반드시 **`/workspace/` 공유 경로에 저장**하여 상대방이 읽을 수 있도록 해야 합니다.
5. **음성 버튼이 사라지면 먼저 입력창 비우기**: 입력창에 비워지지 않은 텍스트나 공백이 남아 있으면 파형 버튼이 숨겨집니다. **입력창을 완전히 비우면** 다시 나타납니다.
6. **고위험 작업은 한 번 허용 선택**: 이메일 발송이나 데이터 수정/삭제 작업 시 '항상 허용'을 선택하지 마세요. 수주일간 안정적으로 운영되기 전까지는 **반드시 '한 번 허용'을 유지**하세요.

## 완료 후 검수 방법

1. `/workspace/` 또는 지정된 디렉터리로 이동하여 파일을 검증하고, 임시 텍스트만 보지 말고 **정상적으로 미리보기가 가능하며 글자가 깨지지 않았는지 확인**하세요.
2. 핵심 데이터 중 2~3곳을 임의로 골라 링크나 스크린샷을 직접 열어보고, 모델의 허위 생성을 방지하세요.
3. 호출 로그를 확인하여 **무단으로 외부 통신을 발송하지 않았는지, 설정을 변경하거나 원본 파일을 덮어쓰지 않았는지 확인**하세요.
4. 사실과 추측을 구분하여 페이지의 실제 문구는 사실 영역에, 추론 및 제안은 비고 영역에 두며, 혼동된 부분은 즉시 바로잡으세요.
5. 예외 목록을 확인하여 **유효하지 않은 웹페이지나 누락된 필드가 있을 때 원인을 명시하고 끝까지 실행**하도록 하며, 오류가 났다고 바로 중단하지 않게 하세요.

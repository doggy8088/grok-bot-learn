# 第13章 事例：Xでのコンテンツ製作と運用

直接スクリプトを書いて投稿APIを高頻度で呼び出すと、リスク管理によってアカウント停止（BAN）されやすく、數日で1週間分の枠（クレジット）を使い果たしてしまいます。

- クラウドVMパイプラインを構築し、WeChatで一言指示を送るだけで、自動的にトピックを検索して初稿を作成します。
- **下書きの作成のみに留め、人間が手動でクリックして投稿する**という原則を守ることで、アカウントの安全を確保しつつ、機械的な単純作業を肩代わりさせます。

## Xプラットフォームのネイティブ機能：読み取り専用検索からリプライ欄でのタスク割り當てまで

![Xプラットフォームのネイティブ機能：読み取り専用検索からリプライ欄でのタスク割り當てまで](/info/13-x-ops-s1.png)

2026-10-08にネイティブの読み取り専用機能がリリースされ、ポスト検索と7日間のトレンド調査はサブスクリプションプールから消費されるようになりました。

2026-10-11の v0.70.2 でアカウント連攜なしでの公開ポスト検索に対応しました。[記録](https://jcng5q8n0f3z.feishu.cn/wiki/ZRFQwIlNgiuJTVkGcJgcrZhsnKd)を參照してください。

|タイプ|アクション|ルールとリスク管理|
|---|---|---|
|ネイティブ読み取り専用|ポスト検索、単一ポスト解析、7日間のトレンド|サブスクリプションプールを消費、アカウント停止リスクなし|
|外部トリガー|リプライ欄での `@bot` 抽出・アーカイブ|スター付きメインBotへルーティング、自動リプライは厳禁|
|アカウント書き込み|ポスト投稿、DM、ブックマーク閲覧、いいね|公式APIを経由、**ヘッドレスブラウザでの投稿は厳禁**|

### 実施方法
1. **対話ウィンドウ**：「過去3日間にXXという話題がどのように評価されているか調べて」と入力するか、リンクを貼って「このポストのコアな視點と読者の議論・対立點を抽出して」と指示します。
2. **リプライ欄**：`@bot 提取本帖核心邏輯並存入選題庫` と返信します。[説明](https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg)を參照してください。

### 検収基準
- **完全な抽出**：元の情報源、投稿日時、議論の流れをすべて取得できていること。
- **応答の境界**：タスク指示後 **30秒以內にログが出力** され、下書きのみを作成して代理投稿は行わず、自動でのいいねや投稿を絶対に行わないこと。

### 検収基準

チャットウィンドウでメインBotにトピック選定と原稿作成のテストを1回実行させます。合格基準として次の2點を満たす必要があります。
- **マルチAgentの実稼働リレー**：メインBotと各擔當Botのバックグラウンドログにおいて、タスクの割り當て、サブBotによる実際の実行、および結果の返卻プロセスが確認できること。
- **下書きの品質とフォーマット規約**：返卻された下書きに機械的なスローガンが含まれず、元の情報源や説明文が本文と混ざらずに本文の下に整然と組態されていること。

## 下書き作成に限定するヒューマンゲートウェイ設計と安全境界

![下書き作成に限定するヒューマンゲートウェイ設計と安全境界](/info/13-x-ops-s4.png)

自動投稿で萬が一モデルのハルシネーション、日付の誤り、不適切なリプライが発生すると、取り返しのつかない損害をもたらします。**パイプラインの最終端には必ず安全のためのヒューマンゲートウェイを設け、投稿、いいね、フォロー、DM、削除の5つのアクションを完全にブロックし、モデルには下書き作成のみを行わせる必要があります。**

### 2層防禦設定

1. **プロンプトでの厳格な指示**：メインBotおよび各擔當Botのプロンプト末尾に次のように固定記述します：
   「デフォルトでは下書きのみを作成すること。投稿、リプライ、いいね、フォロー、DMはユーザーが別途判斷するため、自動実行してはならない。情報源と説明文は、人間が確認しやすく本文のみをワンクリックでコピーできるよう、必ず下書きの外に組態すること」。
2. **システムレベルの遮斷**：Grok Bot の Settings → Custom Rules（または Auto-review）で、**`send`、`post`、`buy`、`transfer`、`delete`、`permissions` を含む操作をすべて「Ask first」にチェックします**。ユーザーが明示的にクリックして承認しない限り、基盤側で実行されることは絶対にありません。

設定規約は『4.3 トリガーと自動化：定期実行、Webhook、Xでのタスク割り當て』[https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg](https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg) を參照してください。

### 検収基準

実際のテスト時に「この下書きを私のXプロフィールに直接投稿して」と指示を出し、合格基準として以下の2點を満たす必要があります：
- **遮斷が機能すること**：Botが実行を明確に拒否するか、システム側で Ask first の承認遮斷カードがポップアップしてAPI呼び出しを停止すること。
- **フォーマットの準拠**：下書き本文と參考リンクが分離されており、文字數がXプラットフォームの制限を厳格に遵守していること。

## 実踐事例の徹底解剖

さまざまなクリエイターがこの體系をどのように日常のワークフローに取り入れているかを直感的に理解できるよう、代表的な3つのコミュニティ実踐事例を詳しく解説します。3つのパターンは、それぞれ異なる規模やニーズの運用フローに対応しています：

| 実踐事例 | クリエイター | コアアーキテクチャと手法 | 參考にすべき重要ポイント |
|---|---|---|---|
| 事例1 | Hardy Chen（@Chchenhao0129） | 5つのBotテンプレート + WeChat ClawBotプラグイン + Webhook | 単一窓口での一元管理、文體・ポジショニングの固定化、ヒューマンゲートウェイによる下書き納品 |
| 事例2 | SCOTTY BEAM（@ScottyBeamIO） | 3つのAgent協調 + クラウドPC共有ディレクトリ + 操作録畫 | 共有ディスクによるデータ中継、固定參照畫像によるトンマナ統一、個別セッションでの定期実行設定 |
| 事例3 | 鐵柱AGI（@cgnot996）、AYi（@AYi_AInotes） | ネイティブ読み取り専用検索 + リプライ欄での `@bot` トリガー + ローカル保存 | 外部APIゼロによるコスト削減とBAN防止、リプライ欄からのアプリ切り替え不要なタスク指示、`/home/box` での永続化 |

### 事例1：Hardy Chen の WeChat一言・5つのBot協調パイプライン

- **誰が**：Hardy Chen（@Chchenhao0129）、個人のコンテンツクリエイター。
- **何を行ったか**：特定機能に特化した5つのBotテンプレートを設定し、WeChat ClawBotプラグインと連攜。WeChatで一言要望を送るだけで、Xのトピック発掘、AIニュースの一次選別、ポストの執筆、週次の投稿データ振り返りまでを全自動で完結させました。
- **どうやったか**：
  1. まずWeb版で公式共有されている5つのBotテンプレートを1つずつ追加し、メインBotを選定した上でシステム初期化プロンプトを送信。自身のアカウントのポジショニング、ターゲット読者、および5つの擔當Botの永続ルーティングをメインBotへ一度に注入しました。
  2. 続いてWeChatインバウンドWebhookと常駐キープアライブリスナーを設定し、スマートフォンのQRコードスキャンでメインBotをWeChatに接続しました。
  3. 毎日のニュース更新用として、Asia/Shanghai タイムゾーンで毎朝7:30の定期タスクを設定し、AIニュースレーダーにAIHOTから情報を収集・元情報源を確認させ、WeChatへプッシュ通知するようにしました。
  4. 投稿データの分析時には、指示に従って管理畫面のCSVファイルを提供し、データ分析擔當Botにエンゲージメント実績を整理させ、翌週のアクション指標を策定させました。
- **參考にできるポイント**：
  - 単一の窓口によるスケジューリング體制を構築し、各擔當Botに1つずつ個別に指示を出す手間を省く。
  - 初期化プロンプトでアカウントのポジショニングを固定し、指示を出すたびに文體を説明し直す手間を避ける。
  - 下書き納品メカニズムを徹底し、下書きの説明と本文を明確に分けてレイアウトする。
  - WeChatに接続しても返信がない場合は、「リスナープロセス → キープアライブタスク → メッセージ重複排除」の標準的な手順に沿って原因を特定し、無闇に連攜解除や再スキャンを繰り返さない。
  - 詳細な振り返りは『WeChatで一言言うだけでXを運用できる：私の5つのBotテンプレートを公開』[https://jcng5q8n0f3z.feishu.cn/wiki/DJwawbQxeiUcIjkKbekcVkHRnye](https://jcng5q8n0f3z.feishu.cn/wiki/DJwawbQxeiUcIjkKbekcVkHRnye) を參照してください。

### 事例3：鐵柱とAYiのXネイティブ検索とリプライ欄 @bot によるナレッジアーカイブ

- **誰が**：鐵柱AGI（@cgnot996）と AYi（@AYi_AInotes）、ヘビーテクニカルリサーチャー。
- **何を行ったか**：2026-10-08にリリースされたネイティブの読み取り専用機能と、2026-10-11の v0.70.2 リプライ欄 `@bot` 連攜機能を活用し、外部APIを一切使わずに業界インテリジェンスの監視とモバイル端末からのワンタップポスト知識アーカイブフローを構築しました。
- **どうやったか**：
  1. 日常的に対話ウィンドウから自然言語で指示を出し、有料コネクターを一切有効化することなく、任意のキーワードに関するXの過去7日間のトレンド推移や主要な議論ポストを抽出。
  2. スマートフォンでタイムラインを閲覧中に長文ポストや技術解説を見つけたら、リプライ欄で直接 `@bot` と返信し、アーカイブの要件を指示。
  3. スター付きメインBotがシステムイベントを受信すると、自動的にポストの全文を取得してナレッジベースでフォーマットを整形し、Markdownファイルとして仮想マシンの `/home/box` ディレクトリ配下に保存・蓄積。
- **參考にできるポイント**：
  - サードパーティ製スクレイパーの代わりに公式ネイティブの読み取り専用権限をうまく活用し、運用保守の複雑さとアカウントBANリスクを大幅に低減する。
  - モバイル端末でアプリを切り替えることなく、`@bot` を通じて軽量にタスクをトリガーする。
  - データのローカル保存を徹底し、クラウドPC內の主要パスを集約してリセットによるデータ消失を防ぐ。
  - 実踐のポイントは『鐵柱ポストまとめ②：プロダクト機能とバージョンの観察』[https://jcng5q8n0f3z.feishu.cn/wiki/ZRFQwIlNgiuJTVkGcJgcrZhsnKd](https://jcng5q8n0f3z.feishu.cn/wiki/ZRFQwIlNgiuJTVkGcJgcrZhsnKd) および『4.3 トリガーと自動化：定期実行、Webhook、Xでのタスク割り當て』[https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg](https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg) を參照してください。

## よくある落とし穴

### 定期実行タスクとクレジット消費
1. 複數のBotを同じTeam Chatに追加した場合、統一したRoutineを保存できません（SCOTTY BEAM による検証済み）。**必ず個別の個人セッションに戻って単體で設定してください**。
2. 一部のバージョンではデフォルトで平日のみ実行されるため、作成指示には「土日を含め、毎日決まった時間に実行」（鐵柱 による検証済み）と明記する必要があります。
3. 北京時間の朝7:30が深夜として実行されてしまわないよう、システム設定でローカルタイムゾーンが Asia/Shanghai になっているか確認してください。
4. Botのクレジット枠はGrokやCursorと共有されており、5分ごとのポーリングでは更新がなくてもコンテキスト全體を読み込んでしまいます。**必ず2段階チェックまたは差分起動（Wake on Done）**に切り替えて一次選別を行ってください。29體のBotを運用する melvindvivas も、生産性の低いルーティンは定期的に整理することを推奨しています。

出典：[『4.3 トリガーと自動化：定期実行、Webhook、Xでのタスク割り當て』](https://jcng5q8n0f3z.feishu.cn/wiki/HHmpwgN4qi86e0kgBvAc1156nkg)

### WeChatとWebhookの接続トラブルシューティング
1. WeChatのQRコードスキャン後に応答がない場合、多くはリスナーのハングアップまたはキープアライブRoutineの停止が原因です。**アカウントの連攜解除と再スキャンを無闇に繰り返さないでください**。Hardy Chen の経験則によれば、デスクトップ側からトラブルシューティングのコマンドを送信してプロセスとキューを確認し、新しいテストメッセージを送信して再疎通を図るのが有効です。
2. v0.68.1 時點でクライアントの詳細カードが開かない場合は、チャット欄にそのトリガーの直通リンクをBotに出力させて確認してください。

出典：[『鐵柱ポストまとめ②：プロダクト機能とバージョンの観察』](https://jcng5q8n0f3z.feishu.cn/wiki/ZRFQwIlNgiuJTVkGcJgcrZhsnKd)

### プラットフォームのインタラクション制限とホスト環境
1. リプライ欄からのタスク指示は動畫のみのポストに対応していません。`@grok` と `@bot` を同時にメンションすると応答しません。悪意あるプロンプトインジェクションを防ぐため、**リプライ欄からのタスク指示には外部への投稿権限を絶対に與えないでください**。
2. 仮想マシンのメンテナンスにより一時パスはリセットされるため、**スクリプト、ドキュメント、バックアップデータは必ず `/home/box` に統一して保存し**、自己修復スクリプトを用意しておいてください。

パス規約：[『鐵柱ポストまとめ②：プロダクト機能とバージョンの観察』](https://jcng5q8n0f3z.feishu.cn/wiki/ZRFQwIlNgiuJTVkGcJgcrZhsnKd)

## 完了後の検収方法

1. メインBotに高評価ポストを3件取得させ、作成者ID、主張、投稿日時を確認し、エラーが発生しないこと。
2. コマンドを送信して履歴を確認し、代理執筆を厳禁とした上で、**5つの擔當Botによるリレー形式で原稿が完成していることを確認**すること。
3. WeChatのClawBotに「初心者の視點でLLMツールに関するショートポストを1本書いて」と送信し、2分以內に下書きが返信されること。
4. 「先ほど生成した下書きを私のXアカウントに直接投稿して」と指示し、**必ずAsk firstが表示され**、承認しない限り外部へ投稿されないこと。
5. Routineの時刻を合わせる。空ファイルを渡し、振り返り擔當Botが欠損をありのままに報告し、データをでっち上げないことを確認すること。

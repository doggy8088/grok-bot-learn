# 第 15 章 事例：EC・日常生活での実踐

Webの対話畫面を単獨で開くだけでは履歴が失われやすく、複數のソフトウェアを行き來してデータを移す手間もかかります。**本章では、既存のソリューションを活用して一連のワークフローを通しで走らせる方法を解説します**。

- 生活・コンテンツ製作：洗練されたプロンプトを使って閒魚の出品文、小紅書のレイアウト、SVG畫像カードを生成し、手作業での位置合わせから解放されます。
- 越境EC：単獨マシンの巡迴チェックから始め、**「船長1名＋12の専門職」チーム**を構築し、承認待ちリストによって人間が最終確認を行います。

## 事例 1：閒魚出品アシスタント（不用品・中古品情報シート＆問い合わせ対応下書き）

Miles Ma（@miles_mazy、著想元は @0xlangeai）がこのBotを作成しました。中古品の出品情報をAIに丸投げすると、**勝手に新品のスペックをでっち上げられてしまうリスク**があります。このBotは、商品の現狀と公式スペックを切り離して処理し、2カラムの情報シートと返信下書きを生成します。

### 手順と検収基準

1. 正面、傷などのアップ、銘板の寫真を撮影し、付屬品、手渡し方法、販売価格を整理します。
2. Grok Bot のサイドバーで `+` をクリックし、「新規Bot作成」を選択して「閒魚出品アシスタント」と命名します。
3. 実物の寫真をアップロードしてプロンプトを送信します（89元の中古Logicool K380sキーボードの例）：

```text
幫我做一份閒魚上架資料。商品是羅技 K380s，黑色，用了 8 個月，空格鍵有輕微磨痕，逐鍵輸入正常，沒拆過機；附兩節在用電池，無包裝，賣 89 元，支援自提，郵費待確認。查官方型號資料，整理標題、商品描述、需要補拍的照片和常見諮詢回覆，做成可打開的資料板，並附可複製的上架正文。沒提供的資訊標為待確認。
```

4. BotがWeb検索で公式サイトのスペックを調べ、HTML情報シートとプレーンテキストの下書きを生成します。

## 事例 2：小紅書エディター（企畫立案から6枚の知識カード＆ギャラリー生成まで）

![事例 2：小紅書エディター（企畫立案から6枚の知識カード＆ギャラリー生成まで）](/info/15-ecommerce-s2.png)

### 作成手順

1. Grok Bot のサイドバーで新規Botを作成し、「小紅書エディター」と命名します。
2. テーマと要點を決定し、カード枚數を6枚に定め、1080×1440のサイズとメインカラー・サブカラーを設定します。
3. 対話畫面に入り、以下のプロンプトを送信します：

```text
給電腦新手做一套小紅書圖文，主題是“Windows 截圖後，圖片去哪了”。查微軟官方資料，做 6 張 1080×1440 的圖：封面、框選截圖、整屏保存、當前窗口、剪貼板歷史、快速鍵對照表。用米白、深藍和亮黃，文字清楚，配操作示意。直接交 PNG 成圖、SVG 源文件和配套發表正文，再做一個能看全套圖片的畫廊。
```

4. **Botが公式ドキュメントを參照してショートカットキーを確認**し、SVGを生成してPNGをレンダリング、HTMLギャラリーにまとめます。

### 検収基準と注意點

| カード | 內容とレイアウト |
| :--- | :--- |
| 1枚目 | 表紙：中央の大きな文字でスクリーンショットに関する悩みを提示 |
| 2〜5枚目 | 手順カード：範囲選択、全畫面などのキャプチャ方法を図解 |
| 6枚目 | まとめカード：4種類のキャプチャ方法と保存先一覧表 |

- カード全體でオフホワイトの背景に濃紺のテキスト、アクセントに鮮やかな黃色を使用します。**1080×1440のPNG畫像6枚、SVGソースコード、ハッシュタグ付きの投稿本文、オンラインギャラリーが納品物として揃っている必要があります**。
- スクリーンショットの自動儲存はシステムのピクチャ設定に依存します。また、**Win + V による履歴確認は事前に設定を有効化しておく必要**があり、履歴が上書きされていないことが前提となります。
- 誤字脫字の修正はテキストエディタで直接SVGを修正すればよく、**畫像を再生成し直す必要はありません**。

## 事例 3：ツール情報リサーチ（用途別にフィルタリング可能なソフトウェア分析レポート）

Miles Ma が作成した「ツール情報リサーチ」Botは、オープンソースリポジトリや公式ドキュメントを収集し、カテゴリ別にフィルタリングできるWebカード型レポートを生成します。

### ツールの制限事項と推奨タスク

| ツール | 匯入ハードルと依存関係 | 主な制限事項 | 推奨タスク |
| :--- | :--- | :--- | :--- |
| **PowerToys** | Windowsインストーラーで直接実行可能 | Windows限定、一部の実験的機能で動作が不安定になる場合あり | ショートカットキーによるテキスト抽出やウィンドウの最前面固定 |
| **MarkItDown** | Pythonまたはコマンドライン環境が必要 | 複雑な図表レイアウトの認識精度に限界あり | WordおよびPDFからMarkdownへの一括変換 |
| **changedetection.io** | Dockerまたはサーバー環境が必要 | インフラ運用の知識が必要、スクレイピング対策の影響を受ける | ECサイトの価格タグ変動の監視 |

### 操作手順

1. Grok Bot のサイドバーで新規Botを作成し、「ツール情報リサーチ」と命名します。
2. 調査対象の読者層とターゲットツールのリストを確定します。
3. 対話畫面に入り、プロンプトを送信します。

```text
幫內容工作室整理 PowerToys、MarkItDown 和 changedetection.io，查官方倉庫和文件。每個工具寫清能幫忙做什麼、上手需要什麼、主要限制，再給一個具體使使用案例子。做成能按用途篩選的網頁簡報，附來源連結。
```

4. Botがリポジトリの説明や依存関係をスクレイピングし、**フィルタリング用スクリプトを含むHTMLレポートを作成**してワークスペースに保存します。

### 検収基準と注意點

- 各カードにはツールの位置付け、匯入前提條件、主な制限事項、実踐タスク、公式サイトのリンクなど、**6つの重要要素が含まれていること**。
- Webページ上部にカテゴリボタンが組態され、カードをスムーズに絞り込めること。
- 制限事項の説明は必ず客観的に行い、changedetection.io にはDockerやサーバーが必要であることを明記し、「ハードルゼロ」などと誇張しないこと。
- これはデスクリサーチによるスクリーニングであり、**Botが全工程の実機テストを行うわけではありません**。匯入要件を満たさない候補ソフトウェアを迅速に除外することを主目的とします。

## 事例 4：動畫チュートリアルクリエイター（インタラクティブ教材ツール＆字幕付きショート動畫）

これは Miles Ma（@miles_mazy、著想元は @0xlangeai）による活用法です。ルービックキューブの時計回り・反時計回りの回転や4回回転による復元は、文章だけで説明するのが難しく、人間が撮影するのも時間がかかります。**Grok Bot はクラウド上でインタラクティブなWebページを構築し、畫面録畫から字幕の焼き込みまでを自動化できます**。

### 実裝手順

1. サイドバーで新規Botを作成し、「動畫チュートリアルクリエイター」と命名します。
2. 完全な解法アルゴリズム全體を扱わず、**1回のセッションで1つの基本動作のみに絞って解説**します。
3. 以下のプロンプトを送信します：

```text
給孩子做一個魔方入門小工具，能認識六個面、點按鈕示範右面順轉和逆轉，再展示右面連續轉四次回到原位。把實際操作錄成一分鐘左右的教學影片，加中文配音和字幕，交付影片和工具文件。
```

4. Botが自動的にWebページを作成し、クリック操作をシミュレートして畫面録畫を行い、中國語字幕付きの動畫を生成します。

### 到達基準（クオリティの目安）

| 納品物 | 検収基準 |
| :--- | :--- |
| **インタラクティブWebページ** | HTML/JSソースコードが保存され、Rをクリックで色が変わり、R'で元に戻り、リセットボタンで4回回転して初期位置に戻ること。オフラインで開けること |
| **完成版動畫** | 約51秒のMP4およびSRT字幕ファイル。畫面の動作と字幕のタイミングが一致していること |

管理畫面のデモや特定の単機能チュートリアルを作成する際にも、このパターンをそのまま応用できます。

## 事例 5：ブックマーク整理マネージャー（SNSのブックマークを企畫ネタ帳へ変換）

![事例 5：ブックマーク整理マネージャー（SNSのブックマークを企畫ネタ帳へ変換）](/info/15-ecommerce-s5.png)

Miles Ma（@miles_mazy）が作成したこのBotは、ブックマークしたコンテンツを企畫ネタのストックに変換します。

### 操作手順

1. サイドバーで新規Botを作成し、「ブックマーク整理マネージャー」と命名します。
2. 代表的なリンクを5種類選びます（ポッドキャスト第115回、畫像・テキスト変換など）。
3. 以下のプロンプトを送信します：

```text
整理這幾條 X 收藏連結，按主題分類，每條留下作者、原連結、核心觀點和可以借鑑的寫法。再圍繞“給新手的 AI 實操課程”提出三個具體選題，做成 Markdown 素材庫和選題清單。
```

4. Botが整理を行い、「ブックマーク素材集」と「企畫提案」の**2つのMarkdownファイル**を生成します。

### 検収基準と制限事項

- 検収基準：**元の著者名と元リンクを保持**し、文章構成のロジックを分解したうえで、3つの企畫を「1回の作業で即座に実行できる粒度」まで具體化すること。
- 制限事項：**他人の実踐結果やデータを自分の體験であるかのように捏造することは厳禁**とし、構成の思考プロセスのみを參考にすること。

## 事例 6：Amazon運用チームの構築（フロント巡迴から「1＋12」の複數役割連攜まで）

![事例 6：Amazon運用チームの構築（フロント巡迴から「1＋12」の複數役割連攜まで）](/info/15-ecommerce-s6.png)

### 背景と役割の定義

- **実踐者**：Zach（@1999Zach22）。
- **実施內容**：元々ローカルの Claude / Codex で実行していたSkillを全面的に Grok Bot へ移行し、共有クラウドPC上に「船長1名＋12の業務擔當」からなるAmazon越境EC AI運用チームを立ち上げました。

### 概要

Codex CLI などのローカルツールはPCを常時起動しておく必要があり、外出先から確認できません。一方、**Grok Bot は24時間稼働の米國クラウドPCを標準搭載**しており、スマートフォンとPCの間でシームレスに連攜できるほか、実際の購入者アカウントを使ってAmazonのフロントエンドを閲覧したり質問したりすることも可能です。

Zach 氏は**「船長1名＋12の業務擔當」**というアーキテクチャを採用しています。ユーザーは船長のみとやり取りを行い、船長が各擔當ポジションを統括・スケジューリングします。

**すべてのポジションにおいて、店舗の管理畫面を直接変更することは厳格に禁止**されており、人間が確認するための「承認待ちリスト」のみを出力します。

| 擔當ポジション | 主な責務 | 厳禁とされる境界線 |
| :--- | :--- | :--- |
| 出海船長 | 部下の統括・割り振り、週報とリストの報告 | 人間を通さずに直接ビジネス上の意思決定を下すこと |
| アシスタント / ハイジャッカー対策 / VOC（顧客の聲） | 相乗り出品の巡迴、商品リサーチ、低評価レビューの分析 | 出品者管理畫面にログインすること、無斷でプロジェクトを立ち上げること |
| 財務 / 広告運用擔當 | 単品利益の試算、広告運用の提案書作成 | 管理畫面にログインして入札額を変更したり除外キーワードを追加したりすること |
| コピーライター / デザイナー / ゲートキーパー（監査） | 広告文や畫像の出力、コンプライアンス最終審査 | 直接本番に公開すること、人間に代わって最終決定すること |
| 振り返りBot | 週次成果の集約、ナレッジベースの更新 | 運用上の課題を隠蔽すること、実績を捏造すること |

### 実踐ステップ

#### 1. サブスクリプションプランと環境の準備
- **入門には月額30ドルのPremiumプランを選択**（月額8ドルのPlusプランにはBot機能が一切ありません）。必要に応じて月額100ドルのSuperプランや月額200ドルのUltraプランへアップグレードします。
- PCとスマートフォンで同一アカウントにログインし、**クラウドPCが正常に稼働していることを確認**します。詳細は [Grok Bot プランと利用量ガイド](https://cursor.com/cn/help/grok-bot/plans) を參照してください。

#### 2. まずは単一のBotで3つのタスクを通しで検証
クラウドPCの米國IPとブラウザを使用して、以下の3つの検証を完了させます：
1. **自社出品（Listing）の日常巡迴**：メイン畫像、価格、バリエーション、相乗り出品をチェックし、例外があれば前日との比較証拠を添えて報告。
2. **AlexaショッピングQ&Aのテスト**：購入者アカウントでログインして質問を行い、約8分間で8種類のシナリオをテストし、過去30日間の価格履歴を調査。
3. **競合商品の定期モニタリング**：価格やクーポンを記録し、**変動があった場合のみ通知**（変動がなければ通知しない）。

```text
每天固定時間去前台檢查自家 Listing：主圖和價格是否正確，變體是否正常掛載，核心關鍵詞是否能搜尋到，是否存在跟賣。只記錄指定商品和關鍵詞，有例外才發提醒，並附帶與前一日的對比資料和頁面截圖證據。不登錄店鋪後台，不執行任何寫操作。
```

```text
從消費者的角度，儘可能多地把 Alexa for Shopping 體驗一遍，最後給我一份報告。
```

#### 3. 機能の分解と各ポジションの境界線設定
- 単一Botで検証が完了したら、タスクを12の業務擔當ポジションに分割します。
- 広告運用や新規出品などの**センシティブな擔當ポジションには、管理畫面への書き込みを明確に禁止**し、すべて「承認待ちリスト」として成果物を提出させ、判斷を仰ぐ境界線を明示します。

```text
你是合理燒錢的廣告投手。負責分析廣告效率、搜尋詞轉化率、出價與預算建議。
邊界約束：
1. 絕對不登錄廣告後台，不直接修改出價，不調整預算，不新增否定關鍵詞，不新建廣告活動；
2. 所有優化建議必須生成「待批清單」，每條建議必須附帶調整依據和預期影響；
3. 待批清單單線交付給出海船長，由船長提報給業務負責人審核，嚴禁自主執行。
```

#### 4. 「1＋N」のタスク引き継ぎチェーンの設計
- **複數のBotによるグループチャットは絶対に作成しないでください**。グループチャットでは全員がコンテキストを重複して受信するため、Tokenが瞬く間に枯渇します。
- **1＋Nアーキテクチャを採用**し、人間は「出海船長」のみとやり取りを行い、船長がタスクを割り振って結果を集約します。

```text
你是出海船長，負責統籌 12 個業務崗位。日常接收業務負責人的目標，拆解為具體子任務派發給對應崗位。所有下屬崗位向你單線彙報，由你彙總結果、審核質量；不達標的打回重做，需要人工決策的整理為帶選項和依據的待批清單彙報給人。嚴格遵守交接鏈規則：
1. 巡檢鏈：助理上報例外與證據，派給資料或廣告崗位做歸因分析；
2. 選品鏈：海盜提交機會報告，財務測算單品利潤，由你整理為立項建議書提報給人；
3. 上新鏈：文案出草稿，設計出圖，守門員審核，你做終檢後交給人確認，由人工在後台發表；
4. 覆盤鏈：收齊各崗位經驗，覆盤機器人寫週報並更新經驗庫，據此編排下週計劃。
所有崗位嚴禁直接登錄店鋪後台或執行未授權的修改操作。
```

#### 5. アセットの共有とローカルPCの実行制御
- すべてのBotが**同一のクラウドPCおよびディスクを共有**するため、スクリプトをワークスペースに組態すれば全員が利用可能になります。
- ローカルファイルを読み込むには、設定の「コンピュータ」ページで**「このコンピュータ上で実行」（Execution on Local Computer）を有効化**し、コピー先ディレクトリを指定する必要があります。

  詳細は [Grok Bot コンピュータとアプリケーションドキュメント](https://cursor.com/cn/docs/grok-bot/work) および [Grok Bot 設定ガイド](https://cursor.com/cn/docs/grok-bot/settings) を參照してください。

## 陥りやすい注意點（落とし穴）

- **出品者管理畫面への変更権限は絶対に付與しない**：機密・重要な操作はBotに「承認待ちリスト」として出力させ、人間が手動で実行することで、価格設定ミスやアカウント停止を防ぎます。
- **閒魚出品での勝手な狀態補完を防ぐ**：「売り手から提供された情報のみを基準とし、未提供の項目は要確認と明記する」と指示することで、公式の新品スペックが紛れ込んで返品トラブルに発展するのを防止します。
- **12個のBotを1つのグループに入れない**：數往復のやり取りだけで1週間分の利用枠を使い果たしてしまいます。「1＋N」のマスター・スレーブ構成を採用し、ファイルのディスク保存を介してデータを受け渡してください。
- **競合データの収集は1日1回が適切**：數分おきのポーリングはIPブロックのリスクが非常に高く、利用枠も消費します。高頻度の監視が必要な場合は公式APIやMCPを利用してください。
- **月額30ドルのPremiumプランを選ぶ**：月額8ドルのPlusプランにはBotへのアクセス権がありません。2026-10-12以降の「The X Subscription」を確認してください。
- **ローカル制御はパス制限を徹底する**：「常に許可」には設定せず、制御前にファイルパスを限定したうえでポップアップ確認を殘し、プライベートなファイルの誤操作を防いでください。

## 完了後の検収方法

**成果物が納品されたら、基準に照らし合わせて1項目ずつ慎重に検証**してください。油斷は禁物です。

- **閒魚情報シート**：傷などの瑕疵と公式スペックが別々に記載され、不明な項目には「要確認」と明記されていること。手渡し場所の勝手な指定やバッテリー狀態の虛偽記載がないこと。
- **小紅書畫像・テキスト**：1080×1440の畫像カード6枚とSVGソースコードが揃っており、操作手順でショートカットキーやシステムの前提條件が明示されていること。カラーパレットが崩れていないこと。
- **ツールレポート**：単一のHTMLページにフィルタリング機能と公式リンクが備わっており、Dockerなどの環境要件・制限事項が正確に記載されていること。匯入難易度を「誰でもすぐできる」などと誇張していないこと。
- **チュートリアル動畫**：完成動畫が約1分間で音聲と映像が同期しており、Web教材ツールのソースコードが添付されていること。字幕と映像のタイミングがずれていないこと。
- **素材集**：元の著者名と元リンクが明記され、企畫ネタが1回の実踐タスクで実行できる粒度に落とし込まれていること。中身のない要約や、他人の事例を自分の體験のように扱っていないこと。
- **EC協調運用**：1＋Nアーキテクチャのもとで船長のみとやり取りを行い、価格変更や出品には必ず承認待ちリストを出力させること。勝手な価格改定や無限ループによる利用枠の枯渇を厳禁とすること。

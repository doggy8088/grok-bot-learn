# 第 16 章 事例：ナレッジ自動取り込みと WeChat 連攜

スマートフォンのブックマークは散らかりがちで、グループチャットのファイルはすぐに期限切れになり、外出先ではクラウドで **24時間365日** 稼働している Grok Bot を活かしきれません。

1. Web ページとショート動畫：Webhook と iOS ショートカットを連攜させ、**ワンタップで構造化して取り込み**。
2. スクリーンショットと音聲録音：WeChat の転送では添付ファイルを引き継げないため、**パブリックな一時中継ストレージを経由**してエクスポート。
3. 対話・タスク実行：公式の「微信ClawBot」プラグインとロングポーリングを利用し、**WeChat のトーク畫面から直接 Grok Bot を呼び出し**。

## 3つの自動化ソリューションの機能と制約の比較

![3つの自動化ソリューションの機能と制約の比較](/info/16-knowledge-s1.png)

| ソリューションと利用シーン | 仕組みと認証 | 注意點・落とし穴 |
| :--- | :--- | :--- |
| 一方向取り込み（Web ページ、公式アカウント記事、ショート動畫） | ショートカットから Bearer キー付きで Webhook に POST して取り込み | 一方向の受信のみ |
| マルチモーダル取り込み（WeChat トーク履歴、録音、スクリーンショット複數枚） | テキストは直接送信。ファイルは filebin.net の一時オンラインストレージを経由して公開リンクを生成し、Bot が解凍して取り込み | **ストレージはパスワードなしのため機密情報送信禁止**。大容量アーカイブのフレーム抽出は token 消費が多い |
| WeChat 雙方向（指示送信、資料検索、Bot 呼び出し） | WeChat の QR コードスキャンで連攜。iLink とクラウドスクリプトで待機し、Webhook に転送してプレーンテキストを返送 | **空回りのリソース消費を防ぐため頻度制限が必要** |

## 事例1：Webhook とショートカットによるナレッジ自動取り込みパイプラインの構築

![事例1：Webhook とショートカットによるナレッジ自動取り込みパイプラインの構築](/info/16-knowledge-s2.png)

**本ソリューションでは、スクレイピング、音聲・動畫の文字起こし、要約のすべてを Grok Bot クラウド側で処理し、スマートフォンからは URL を送信してトリガーするだけです。

** 鐵柱AGI（@cgnot996）は[ルーティン](https://cursor.com/cn/help/grok-bot/routines)の Webhook を利用し、リクエスト送信即起動を実現しました。

### 構築手順
1. デスクトップ版の Details から Routines を開きます。Bot に解析タスクを作成させ、**生成された Webhook URL と key を大切に保管**します。
2. ショートカット「ナレッジベース Bot へ送信」を新規作成し、「URL の內容を取得」を追加して表のとおりパラメータを設定します。

| パラメータ | 設定値 |
|---|---|
| URL | Webhook アドレス |
| 方法 | POST |
| ヘッダー | キー名 `Authorization`、値 `Bearer <key>` |
| リクエスト本文 | JSON を選択し、「ショートカットの入力」を追加 |

3. **閉鎖的なアプリ向けに補助入力ダイアログを追加**。WeChat では共有シートが無効化されていることが多いため、2つ目のショートカット（「メニューから選択」と「テキストを要求」）を中継用として作成し、iPhone のアクションボタンに割り當てて、ボタンを押すだけで貼り付けて送信できるようにします。

## 事例2：WeChat トーク履歴とマルチモーダル素材の連攜・取り込み

### 事例の概要
- WeChat のまとめ転送をパッケージ化して Grok Bot に送信すると、自動解凍されて結果（受領証）が返信されます。
- **filebin.net を踏み台として利用し**、ローカルパスへの依存を排除。
- Mac と iPhone に **5つの取り込みモード** を備えたショートカットを配備。

### 概要：なぜ一時的なオンラインストレージの中継が必要なのか

デバイス間ではローカルディスクを直接読み取れず、WeChat の大容量 ZIP ファイルをリクエスト本文に直接含めるとタイムアウトしやすいためです。

1. テキストは JSON 経由で直接送信します。
2. 畫像、録音、ZIP ファイルはまず filebin.net にアップロードし、そのリンクを Bot に送信してダウンロードさせます。
3. ストレージ ID には、名前の衝突による情報漏洩を防ぐため、**最低8文字のランダムな英數位**を使用する必要があります。
4. ファイルはデフォルトで7日間保持され、暗號化されていないため、**プライバシー情報や機密情報の送信は厳禁**です。

### 実踐：ステップ別の構築手順

#### 1. Webhook の設定
デスクトップ版のメインチャットで次のプロンプトを送信します：

```text
幫我建立一個 Webhook 觸發的例行任務。快捷指令會用 POST 請求發來一個 JSON，裡面只有一個欄位 info。info 可能是我輸入的文字，也可能是一個文件下載連結，比如微信聊天記錄壓縮包、截圖、錄音。收到後：如果是連結就先下載文件再讀取，壓縮包先解壓；然後整理出要點，收錄進知識庫，最後給我一份回執，寫清楚收錄了什麼、存在哪裡。
```

**送信後、Bot の「ルーティン」で Webhook URL と key を記録します。**

#### 2. ショートカットの設定
インポートリンク：`https://www.icloud.com/shortcuts/2b77155d7c744110a0f0f9ef1bdc42bf`
「【共有版】ナレッジベース Bot へ送信」を編集し、URL、key、および **8文字以上の複雑なストレージ ID**（例：kb7x9m2q）を入力します。ヘッダーは組み込み済みのため変更不要です。

#### 3. WeChat トーク履歴の取り込み
- **Mac 版**：他のアプリへまとめ転送する際に該當のショートカットを選択し、「転送を受信」をクリック。ZIP がオンラインストレージにアップロードされてリンクが送信され、Bot が即座に処理を開始します。
- **スマートフォン版**：まとめ転送時に該當のショートカットを選択し、「転送を受信」をタップ。「アクションを編集」からよく使う項目に固定しておくことも可能です。

#### 4. 単獨での呼び出しと収集
Mac では Raycast やメニューバーから、スマートフォンではアクションボタンに割り當てて呼び出します。
- スクリーンショット／録音：確認または録音完了後、オンラインストレージにアップロードしてリンクを送信。
- テキスト入力：オンラインストレージを経由せず、**JSON に直接含めて送信**。
- 畫像を選択して補足：畫像を選択した後に説明を入力し、まとめてアップロード。
- 転送を受信：コンテンツを受信していない場合は、クリップボードの內容を読み取って送信。

## 事例3：Grok Bot を WeChat に直接接続して雙方向にタスクを実行する

![事例3：Grok Bot を WeChat に直接接続して雙方向にタスクを実行する](/info/16-knowledge-s4.png)

### 事例の概要
Kin 氏は Grok Bot を WeChat に連攜させ、**スマートフォンからメッセージを送るだけでクラウド上の Bot を遠隔操作**できるようにしました。

1. Grok に iLink を呼び出すロングポーリングスクリプトを作成させる
2. 指示を受信する Webhook を構築する
3. WeChat で「微信ClawBot」を有効化し、QR コードをスキャンして連攜する

完全なアウトバウンドロングポーリングを採用しているため、**パブリックな受信ポートを開放する必要はありません**。

### 概要：微信ClawBot と iLink のロングポーリングの仕組み

本ソリューションは公式の「微信ClawBot」プラグインと iLink インターフェース（`ilinkai.weixin.qq.com`）を利用しており、クライアントのメモリ改変を行わないため、**アカウント停止のリスクがありません**。

通信はすべてアウトバウンドリクエストであり、**パブリックポートの開放は不要**です：
1. Grok Bot がバックグラウンドで `getupdates` をポーリングしてメッセージを取得し、処理完了後に `sendmessage` を呼び出して返信します。
2. Webhook でテキストを受信後、各専門 Bot に引き渡して連攜処理を行います。詳細はドキュメント[Grok Bot の使用](https://cursor.com/cn/docs/grok-bot/work)をご覧ください。

### 実踐：ステップ別操作手順と完全なプロンプト

1. PC 版のメインチャットでプロンプトを送信し、「微信下旨入口」ルーティンが作成されるのを待ちます。
::: details 実踐：ステップ別操作手順と完全なプロンプト
```text
我想把你接到我的微信上，讓我能在微信裡直接給你發訊息、收到你的回覆。請按下面的思路做，每做完一步告訴我結果，需要我操作的地方停下來等我。

1、先調研方案：騰訊「微信ClawBot」外掛用的是 iLink 介面（ilinkai.weixin.qq.com）。請確認怎麼用 getupdates 長輪詢收訊息、怎麼用 sendmessage 回訊息。整個程式只走出站請求，不要開公網端口。

2、在 Grok Bot 裡建一個由 webhook 觸發的 routine，名字可以叫「微信下旨入口」。建好後告訴我去 routine 面板複製 Webhook URL 和 key，然後彈出加密彈框讓我填進去，不要讓我在聊天裡發明文。

3、在你的雲端電腦上寫一個小轉發程式：收到微信訊息後 POST 給這個 routine；你處理完以後，用一個 reply 指令碼把回覆發回微信，同時在我們的主聊天裡同步一份。

4、等我在手機微信裡啟用 ClawBot 外掛以後，生成二維碼讓我用手機掃碼確認，同時給我一個可以在微信裡直接打開的備用連結。二維碼大約 5 分鐘有效。

5、綁定成功後，提醒我先在 ClawBot 對話裡發一句話，因為回覆要用到這條訊息帶的 context_token。

6、規則：只認綁定的這一個人，別人的訊息不處理；回覆一律用純文字，不要用 Markdown，因為微信不渲染 Markdown。

7、最後告訴我：雲端電腦重啟以後，怎麼把轉發程式重新拉起來；如果遇到錯誤碼 -14（憑證過期），提醒我重新掃碼。
```
:::
2. ルーティンの URL と key をコピーします。**チャット欄に平文で送信することは厳禁**です。シークレットカードに入力し、「安全に保存され、非公開に保たれています」と表示されれば完了です。詳細は[機密情報の安全な保管](https://cursor.com/cn/help/grok-bot/secrets)をご覧ください。
3. WeChat のバージョンは **iOS 8.0.70 / Android 8.0.69 以上** である必要があります。「自分」->「設定」->「プラグイン」で赤いロブスターのアイコンの「微信ClawBot」を有効化します。
4. 「プラグインを有効化しました」と送信し、WeChat で QR コードをスキャンして認証します（QR コードの有効期限は **5分間** です。期限切れの場合は予備リンクを使用してください）。
5. **必ず WeChat 側から最初にメッセージを1通送信してください**（例：「こんにちは」）。API が接続確立のために `context_token` を取得する必要があるためで、送信が完了すると通信チャネルが正式に確立されます。

## よくある落とし穴

1. 転送する前に**必ずローカルで添付ファイルをタップしてダウンロード**してください。そうしないと、エクスポートされた ZIP にプレースホルダーのテキストしか殘りません。
2. filebin.net にはパスワードがないため、`test` や `123456` などの安易な文字列は避け、**必ず8文字以上のランダムな文字列を設定**してください。身分証、銀行カード情報、機密契約書などのアップロードは厳禁です。
3. Webhook の設定時にチャット欄へ直接 key を貼り付けず、**シークレットカードを使って安全に保存**してください。ショートカットを共有する前には、個人の key や URL を必ず削除してください。
4. ClawBot の QR コードは5分で無効になります。応答がない場合や `-14` が返される場合は**認証情報が期限切れ**であることを意味するため、再生成してスキャンし直す必要があります。
5. クラウド PC がリセットまたは再起動されると Python のポーリング処理が停止します。WeChat から応答がない場合は、デスクトップ側で **Bot にスクリプトを再起動させて**ください。
6. WeChat は Markdown をレンダリングしないため、**Instruction でプレーンテキストでの返信を強制**し、`**` や `#` などの記號を出力しないようにします。
7. iLink キューでのメッセージ競合による指示の取りこぼしを防ぐため、**複數の OpenClaw リスナーを同時に実行しないでください**。
8. The X Subscription は週ごとのクォータから差し引かれるため、**高頻度でトリガーされる処理には必ずフィルタリングを入れてください**。消費が早すぎる場合は、不要なルーティンを一時停止するか、トリガー條件を緩和してください。

## 完了後の検証手順

1. **Webhook のテスト**：`Authorization: Bearer <key>` を付與した POST リクエストを送信します。**ステータス 200 が返ってくれば成功**です。401 はキーの誤り、404 は URL の誤りです。PC 側の「ルーティン」のステータスが Running… に変わり、ログが出力されていれば問題ありません。
2. **ショートカットのテスト**：テキストを送信して數十秒以內に結果（受領証）が返ってくるかをテストし、畫像2枚を転送してアーカイブをテストします。スクリーンショットは必ずアクセス許可のプレビューが表示され、「許可」をタップして初めて送信される挙動になっていることを確認します。
3. **WeChat と同期のテスト**：「微信ClawBot」にメッセージを送信し、**5秒以內に返信があれば成功**です。さらに PC 側を確認し、チャット履歴が同期されていれば完全に開通しています。

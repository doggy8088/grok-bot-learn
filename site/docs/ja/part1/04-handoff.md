# 第4章 タスクの指示：メッセージ、添付ファイル、そして適切な引き継ぎ

要件があまりに簡潔すぎると、Bot は無関係な Web ページを何十件も検索したり、ファイルを亂雑に変更したりしがちです。**メッセージの送信とは、クラウド PC に作業を引き継ぐことにほかなりません**。

- **タスクの境界を厳格に定め**、添付ファイルの用途を明記して、勝手な判斷を防ぐ
- 明確な指示を出し、直接検収可能な成果物を受け取る
- 実行中も隨時口を挾んで軌道修正するか、音聲で背景情報を補足する


![タスクの指示：メッセージ、添付ファイル、そして適切な引き継ぎ](/info/04-handoff.png)

## 優れたリクエストの5大要素

![優れたリクエストの5大要素](/info/04-handoff-s1.png)

Grok Bot にタスクを指示する際は、**指示において目標とツールの範囲を明確にする必要があります**。仕様の詳細は [『Grok Bot』](https://cursor.com/cn/docs/grok-bot) ドキュメントを參照してください。

1. **アクションは具體的かつ単一にする**。「スクレイピングして比較」や「外部向けメールの下書き作成」のように明記し、「少し調べておいて」といった曖昧な表現は避けます。経路が短いほど無駄なステップを省けます。
2. **データソースを限定する**。Notion ページ、Slack の #sales-leads チャンネル、あるいは特定の URL を指定し、Web 全體を無作為に検索するのを防ぎます。
3. **承認のレッドラインを明確にする**。読み取りや比較は自動で実行させますが、**外部へのメール送信、オンライン決済、データの変更・削除を伴う場合は、必ず一時停止して承認を待たせます**。
4. **成果物の形式を固定する**。**口頭での報告は受け付けず**、`/workspace/leads/` にリンク付きの Markdown レポートまたは CSV テーブルを生成するよう要求します。
5. **エラー処理ルールと事実の境界を定める**。推測と客観的事実を區別させます。ログインが無効になった場合はスキップして記録を殘し、**無限ループでの再試行を禁止します**。

## 添付ファイルの仕様と制限一覧

アップロードルールについては [『Grok Bot の使用』](https://cursor.com/cn/docs/grok-bot/work) を參照してください。

### 仕様制限

- デスクトップ版は1件につき**最大6個まで**（上限を超える場合はワークスペースに組態）。畫像・テキスト・音聲は 25MB まで、動畫は 200MB まで。
- 処理が止まったりエラーが発生したりした場合は、まずローカルで PDF、CSV、または畫像に変換してからアップロードしてください。

### 引き継ぎとグループチャット

1. **ファイルをドラッグ＆ドロップした後にすぐ Enter を押さないこと**。各ファイルの役割、関連ロジック、および保護に関する注意事項を明記してください。

```text
上傳的 PDF 是已經簽署的標準採購合同樣板。上傳的 Excel 是本月供應商提交的實際報價清單。
請對照合同樣板中第 4 條關於各類物料的基準單價，逐行核驗 Excel 裡的實際報價。
標出單價超出基準價的所有條目，在附帶的備忘中引用合同中的對應條款編號。
將核驗結果另存為一份新的 Excel 表格，並輸出一份簡短的例外摘要。
請勿改動原始上傳文件。
```

2. グループチャット內の Bot 間では**プレーンテキストのみをサポート**しています。後続の Bot に添付ファイルを參照させたい場合は、個別のダイレクトチャットで送信する必要があります。

## タスク引き渡しの実用プロンプト集

よくあるシナリオでは**テンプレートをそのまま流用**し、少し手を加えるだけですぐに使えます。

1. **リサーチとアウトリーチ**：リードの調査と資料の準備を行い、直接送信はしない。
```text
從我們的 CRM 系統中獲取本週銷售管道的重點評審列表。
請跳過當前已經處於活躍跟進序列中的聯繫人。
在指定公開網頁和已授權的 Slack 相關頻道中，深入調研排名前五的重點帳戶，找出負責採購或技術的對口聯繫人。
參考我在系統中歷史郵件的口吻，為這五位聯繫人分別起草個性化的初次外聯郵件。
將草稿保存在系統草稿箱中，並在明天上午 9 點前在此對話中列出清單供我審批。未經我的明確確認，絕不向外發送任何郵件。
```
2. **添付ファイルの検証**：複數テーブルの突き合わせと収支の確認。
```text

1. 檢查報銷金額是否超過對應城市級別的住宿與餐飲標準。
2. 檢查單筆超過 500 元的支出是否有對應的發票類別標記。

最後生成一份 Markdown 格式的核查報告，並列出通過與未通過的統計彙總。保持原始 CSV 文件不被改動。
```

## 長期ルールと単発タスク：「家訓」と「家事」を混同しない

![長期ルールと単発タスク：「家訓」と「家事」を混同しない](/info/04-handoff-s4.png)

**長期ルールと単発タスクを明確に區別し**（[『Grok Bot の使用』](https://cursor.com/cn/docs/grok-bot/work) を參照）、一時的なパラメータを長期設定に書き込んだり、毎回ゼロから最低限のルールを指示し直したりしないようにしましょう。

| タイプ | 有効期間と設定方法 | 例と制限 |
| --- | --- | --- |
| 長期ルール | セッションをまたいで有効。Bot Details で設定するか、「これを長期ルールとして記憶領域に記録してください」と入力 | 権限のレッドライン、日付フォーマット YYYY-MM-DD |
| 単発タスク | 単一ターンのみ有効で蓄積されない。直接指示を出す | 12件のアカウントまたは3件の音聲の処理、10時の會議のアジェンダ抽出 |

すべての Bot は `/workspace` を共有します（[『10 條の必須経験：Grok Bot をより使いこなすために』](https://jcng5q8n0f3z.feishu.cn/wiki/Hfqxwy3zQiWkRPkVjRZcVCuHnbc) を參照）。

**記憶は業務システムの代わりにはなりません**。殘高や在庫情報は必ず正規のソースから取得する必要があり、勝手な憶測は厳禁です。

## タスク進行中の介入：停止、割り込み、そして承認

![タスク進行中の介入：停止、割り込み、そして承認](/info/04-handoff-s5.png)

### 割り込みと停止
Bot が目標から外れた場合は、通常のメッセージを送信するだけで**即座に割り込み**が可能です。例えば「2026年10月更新の改訂版仕様に切り替えて再調査して」のように送信します。

操作に誤りがあったり高リスクな呼び出しが発生したりした場合は、入力欄に以下の4文字を送信して停止させます。
```text
立即停止
```

**停止は未実行のアクションを遮斷するだけであり、保存済みのファイルや送信済みの API リクエストをロールバックすることは決してありません**。停止後は以下の3ステップで確認・対処します。
1. クラウド PC のプレビューパネルを開いて狀態を確認する。
2. 作りかけの成果物や誤って書き込まれた內容をクリーンアップする。
3. 範囲を絞り込み、境界を明確にしてから再開する。

### 承認とタイムアウト
Auto-review を有効にしている場合や高リスクな操作がトリガーされた場合は、「操作のレビュー」カードが表示されます（[『Grok Bot 操作ガイド』](https://cursor.com/cn/help/grok-bot/how-to) を參照）。これには3つの選択肢が含まれます。
- 1回のみ許可：今回のみ承認し、次回以降の同種の操作では再度確認する。
- 常に許可：ホワイトリストに追加し、以降は通知を表示しない。
- 拒否：その操作を完全に遮斷する。

| シナリオ | 待機メカニズム | タイムアウト時の結果 |
| --- | --- | --- |
| リアルタイム対話 | 保留して待機 | クリックして処理するまで待機を継続 |
| バックグラウンド無人実行 | 約10分で自動期限切れ（Expired） | **操作を実行せずにタスクを終了** |

### 認証情報の引き継ぎ（Action needed）
パスワード、2FA、CAPTCHA、または実際の決済が関係する場合、引き継ぎカードが表示されます。以下の3ステップで操作してください。
1. **Take over** をクリックしてクラウド PC 上で手動入力する。
2. 完了後、**I'm done** をクリックして制御権を返卻する。
3. **通常の対話入力欄には絶対に平文のパスワードを入力しないこと**。

## 音聲操作：リアルタイム音聲通話と音聲文字入力の使い分け

Grok Bot には音聲入力（文字起こし）と通話という**2つの異なる音聲機能**が備わっています。詳細については [『Bot との音聲チャット』](https://cursor.com/cn/help/grok-bot/voice-chat) および [『Grok Bot 操作ガイド』](https://cursor.com/cn/help/grok-bot/how-to) を參照してください。

### 2つのモードの比較

| モード | 起動方法とショートカットキー | 出力と主な利用シーン |
| --- | --- | --- |
| 音聲入力（ディクテーション） | デスクトップで「音聲入力を開始」をクリック、Mac は Cmd+D、Win/Linux は Ctrl+D、スマートフォンでは「聞き取りを開始」をタップ | 入力欄にテキストが入力される。プロンプトの微調整やパラメータ追加に最適 |
| リアルタイム音聲チャット | **入力欄を完全に空にした**後、波形アイコン（Start voice chat）をクリック | 雙方向リアルタイム通話。アイデアの整理や迅速な引き継ぎに最適 |

### 開始手順と落とし穴の迴避

1. 個別の Bot チャットを開く。
2. **入力欄は完全に空にする必要があります**。スペースや下書きが少しでも殘っていると、波形アイコンが非表示になります。
3. 波形アイコンをクリックします。初回利用時はマイクのアクセス許可が必要です。
4. Connecting…（スマートフォン版では Calling…）と表示され、Bot が自発的に話し始めれば接続完了です。

### コントロールと制限事項

- 通話中はミュート、スクロール字幕の表示、話速や音色の調整が可能です。畫面を切り替えて資料を確認する際は、上部バーの「音聲チャットに戻る」をクリックすればすぐに復帰できます。
- **1対1の個別チャットのみ対応**しています。グループチャット、複數 Bot グループ、「チーム Bot」からは開始できません。
- **同時に維持できる通話は1つのみ**です。新しい Bot に切り替えるには、「終了してチャットを開始」を確認する必要があります。
- 通話を切斷すると自動的に Voice chat カードが生成されて総通話時間が記録され、クリックして全文テキストを確認できます。その後のタスクはテキストチャット上でそのまま進められます。

## よくある失敗例と改善の対比

1. **実行パスの収束**：範囲と方法を定めていないと、Bot はコンソールを手當たり次第に操作し、**本番環境のコードを変更してしまうことすらあります**。
```text
  幫我維護一下網站，看看有沒有什麼 Bug。
  ```
対象ページと調査ステップを限定するように変更：
```text
  對站點清單（/workspace/sites.txt）中的三個靜態展示頁進行巡檢。
  用雲端瀏覽器打開每個頁面，檢查主控台是否有 404 或 500 報錯，檢查頂部導覽欄連結是否全部有效。
  將報錯資訊、對應頁面 URL 及當時的螢幕截圖寫入 /workspace/logs/err-20261014.md。
  全程僅做唯讀檢查，嚴禁點選任何帶有提交或刪除性質的表單按鈕。
  ```

2. **承認の境界**：外部への送信権限を與えないこと。解釈が脫線した場合、**重要な顧客に誤った內容を送信してしまうリスクがあります**。
```text
  讀取 Gmail 裡的未讀郵件，重要的直接幫我回一下。
  ```
重要なチェックポイントでは人間が承認を行うように変更：
```text
  讀取 Gmail 中過去 12 小時的未讀郵件。
  僅篩選出發件人屬於我們現有企業客戶、且正文包含售後或諮詢訴求的郵件。
  根據產品常見問題手冊，為每封郵件起草回覆草稿並存入 Gmail 草稿箱。
  在當前對話中列出客戶名稱、郵件摘要與草稿正文，等待我的審批。未經我的明確確認，絕不點選發送。
  ```

3. **事実と推測の分離**：プロンプトに先入観を混ぜないこと。**Bot が仮説に迎合して、小規模なセールを価格競爭だと誤認するのを防ぎます**。
```text
  去看看競品今天的動態，總結一下他們是不是要跟我們打價格戰。
  ```
客観的なデータと推測を分けるように変更：
```text
  訪問競品官網的公開定價頁與首頁橫幅，獲取他們當下的方案價格表。
  對照我們在 /workspace/competitor/last-month-price.json 中記錄的舊價格：
  1. 事實列：標出哪些 SKU 的標價發生了變動，變動金額是多少，附帶頁面截圖與訪問時間。
  2. 推測列：基於該降價是限時促銷還是永久調價，給出你的分析理由。
  兩部分內容必須分開分欄呈現，不得將分析推論當作已知事實。
  ```

4. **読み取り専用の保護**：主テーブルと従屬テーブルの関係や保持すべきフィールドを指示しないと、**元データが上書きされて破損するリスクが極めて高くなります**。
```text
  （直接拖入三個 Excel 表格）把這幾個表整理一下。
  ```
どのテーブルを基準にするかを明確にし、読み取り専用として指定するように変更：
```text
  上傳的三個表格分別是 7 月、8 月和 9 月的銷售明細。
  以「訂單編號」為唯一主鍵進行資料去重合並：
  1. 欄位統一保留：訂單號、成交日期、客戶名稱、銷售代表、成交金額。
  2. 生成一份全新的 Q3_sales_summary.csv 文件，保存在當前工作區。
  3. 保持我上傳的原始 7、8、9 月表格內容與檔名完全不變。
  ```

5. **単一の責務**：1つの Bot に複數のタスクを詰め込まないこと。記憶が混亂するだけでなく、**週間利用枠を急速に使い果たしてしまいます**。
```text
  你幫我寫一篇關於新產品的推文，順便把昨天的帳目算了，然後再幫我看看競品推特。
  ```
単一タスクに分割して役割分擔させるように変更：
```text
  遵循一個 Bot 負責一項核心任務的原則。當前 Bot 僅承擔社媒文案起草職責：
  依據 /workspace/product/spec.md 中的新功能說明，為 X 平台起草三條不同風格的發表文案。
  要求突出效能提升資料，字數控制在 280 字元以內。
  帳目核算與競品調研交由對應的專用 Bot 負責，不要在此會話中處理。
  ```

## 実際の業務引き継ぎ事例

## 陥りやすい落とし穴

1. **添付ファイルには説明を添える**：複數の畫像や2つ以上のテーブルを送信する際は、**必ず用途を明記してください**。そうしないと主従関係を取り違えやすくなります。
2. **長期ルールは記憶領域に保存する**：単発の指示はセッションが変わると失われます。基本規範やレッドラインは **Bot の詳細にある「About / 役割」に記述する**か、記憶領域に保存してください。
3. **ローカル連攜時はスリープを防止する**：純粋なクラウド実行ならノート PC を閉じても動き続けますが、ローカル PC と連攜している場合はスリープすると接続が切斷されます。**電源とスリープの設定を忘れずに確認してください**。
4. **Bot 間の畫像受け渡しはパス経由で行う**：グループ內の Bot 間ではプレーンテキストのみがサポートされています。畫像を渡す場合は、**共有パス `/workspace/` に保存して**相手に読み取らせる必要があります。
5. **音聲ボタンが消えたらまずは入力欄を空にする**：入力欄に未消去の文字やスペースが殘っていると波形ボタンが非表示になります。**入力欄を完全に空にすれば**元に戻ります。
6. **高リスクな操作では「1回のみ許可」を選択する**：メール送信やデータの変更・削除では「常に許可」を選ばず、安定して數週間運用できるまでは、**「1回のみ許可」を選び続けてください**。

## 完了後の検収方法

1. `/workspace/` または指定されたディレクトリに行動してファイルを確認し、**正常にプレビューでき、文字化けがないことを確認します**。一時的なテキスト表示だけで判斷しないでください。
2. 2〜3箇所の重要なデータを無作為抽出し、リンクを開くかスクリーンショットを確認して、モデルによる作り話（ハルシネーション）を防ぎます。
3. 呼び出しログを確認し、**無斷で外部通信を行っていないか、設定の変更や元ファイルの上書きをしていないかを確認します**。
4. 事実と推測を明確に區別し、ページ上の原文は事実エリアに、推論や提案は備考エリアに記載させ、混同している場合はその場で修正します。
5. 例外一覧を確認し、**無効な Web ページや欠損フィールドがあった場合は理由を記録した上で最後まで実行されていること**を確認します。エラーが出たからといって即座に中斷させないようにします。

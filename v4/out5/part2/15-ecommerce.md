# 第 15 章 案例：電商與生活實操

單開網頁對話框容易丟記錄，還得多頭切軟體搬運。**這章帶你用現成方案跑通流程**。

- 生活與內容：拿成熟提示詞生成閒魚文案、小紅書排版和 SVG 圖卡，不再手動對齊。
- 跨境電商：從單機巡檢起步，搭出 **「1 船長 + 12 崗位」團隊**，用待批清單人工把關。

## 案例 1：閒魚上架員（二手閒置資料板與諮詢草稿）

Miles Ma（@miles_mazy，靈感源自 @0xlangeai）做了這個 Bot。賣二手直接丟給 AI **容易被瞎編成全新組態**。它把實況與官網參數分流，生成雙欄資料板和回覆草稿。

### 步驟與驗收

1. 拍好正面、瑕疵特寫和銘牌，理清配件、自提方式與售價。
2. 在 Grok Bot 側邊欄點 `+` 選「新建 Bot」，起名「閒魚上架員」。
3. 上傳實拍圖發提示詞，以標價 89 元二手羅技 K380s 鍵盤為例。

```text
幫我做一份閒魚上架資料。商品是羅技 K380s，黑色，用了 8 個月，空格鍵有輕微磨痕，逐鍵輸入正常，沒拆過機；附兩節在用電池，無包裝，賣 89 元，支援自提，郵費待確認。查官方型號資料，整理標題、商品描述、需要補拍的照片和常見諮詢回覆，做成可打開的資料板，並附可複製的上架正文。沒提供的資訊標為待確認。
```

4. Bot 聯網查官網參數，生成 HTML 資料板與純文字草稿。

## 案例 2：小紅書編輯（從選題到六張知識圖卡與畫廊）

### 製作步驟

1. 在 Grok Bot 側欄新建 Bot，取名「小紅書編輯」。
2. 敲定選題與知識點，把卡片定為 6 張，設好 1080×1440 尺寸與主輔配色。
3. 進入對話介面，發送提示詞：

```text
給電腦新手做一套小紅書圖文，主題是“Windows 截圖後，圖片去哪了”。查微軟官方資料，做 6 張 1080×1440 的圖：封面、框選截圖、整屏保存、當前窗口、剪貼板歷史、快速鍵對照表。用米白、深藍和亮黃，文字清楚，配操作示意。直接交 PNG 成圖、SVG 源文件和配套發表正文，再做一個能看全套圖片的畫廊。
```

4. **Bot 會查閱官方文件核對快速鍵**，生成 SVG 並渲染 PNG，整合成 HTML 畫廊。

### 驗收與避坑

| 卡片 | 內容與排版 |
| :--- | :--- |
| 第 1 張 | 封面，大字居中點出截圖要害 |
| 第 2-5 張 | 步驟卡，圖解框選、全螢幕等截圖方式 |
| 第 6 張 | 總結卡，4 種截圖方式與去向表 |

- 全套卡片採用米白底色配深藍文字，亮黃點綴。**必須交付 6 張 1080×1440 PNG、SVG 原始碼、帶標記正文與線上畫廊**。
- 截圖自動落盤依賴系統相冊設定，**Win + V 查歷史必須提前打開開關**，且記錄未被覆蓋。
- 改錯別字直接在文字編輯器裡改 SVG，**不用重新生圖**。

## 案例 3：工具情報員（按用途篩選的軟體分析簡報）

Miles Ma 做的「工具情報員」Bot，專門抓取開源倉庫與文件，生成支援分類篩選的網頁卡片簡報。

### 工具限制與推薦任務

| 工具 | 門檻與依賴 | 主要限制 | 推薦任務 |
| :--- | :--- | :--- | :--- |
| **PowerToys** | Windows 安裝包直接執行 | 僅限 Windows，部分實驗功能偶發不穩定 | 快速鍵提取文字或置頂窗口 |
| **MarkItDown** | 依賴 Python 或命令列 | 複雜圖文版面識別率有限 | 批量轉 Word 與 PDF 為 Markdown |
| **changedetection.io** | 需 Docker 或伺服器環境 | 需運維基礎，受反爬限制 | 監控電商價格標記變動 |

### 操作步驟

1. 在 Grok Bot 側欄新建 Bot，命名為「工具情報員」。
2. 確定調研受眾與目標工具清單。
3. 進入對話介面發送提示詞。

```text
幫內容工作室整理 PowerToys、MarkItDown 和 changedetection.io，查官方倉庫和文件。每個工具寫清能幫忙做什麼、上手需要什麼、主要限制，再給一個具體使使用案例子。做成能按用途篩選的網頁簡報，附來源連結。
```

4. Bot 抓取倉庫說明與依賴，**編寫包含篩選指令碼的 HTML 簡報**存入工作區。

### 驗收標準與避坑

- 每張卡片**包含 6 項核心要素**，覆蓋工具定位、上手依賴，以及主要限制、實操任務與官網連結。
- 網頁頂部設定分類按鈕，能平滑篩選卡片。
- 限制說明務必客觀，明確指出 changedetection.io 需 Docker 或伺服器，不誇大為零門檻。
- 這屬於案頭篩選，**Bot 不跑全流程實測**，主要用來快速排除不符合門檻的候選軟體。

## 案例 4：影片課程師（可交互教學工具與帶字幕短影片）

這是 Miles Ma（@miles_mazy，靈感源自 @0xlangeai 藍哥 AI）的玩法。魔方順逆轉動與四次復位很難文字講清，人工實拍又耗時。**Grok Bot 能在雲端寫出交互網頁，並自動螢幕錄影壓制字幕**。

### 怎麼做

1. 側欄新建 Bot，命名為「影片課程師」。
2. **每次只講一個基礎動作**，避開全套還原演算法。
3. 發送提示詞：

```text
給孩子做一個魔方入門小工具，能認識六個面、點按鈕示範右面順轉和逆轉，再展示右面連續轉四次回到原位。把實際操作錄成一分鐘左右的教學影片，加中文配音和字幕，交付影片和工具文件。
```

4. Bot 自動寫網頁、模擬點選並螢幕錄影，生成帶中文字幕的影片。

### 做到什麼程度算好

| 交付項 | 驗收標準 |
| :--- | :--- |
| **交互網頁** | 留存 HTML/JS 原始碼，點 R 換色，點 R' 復原，復位按鈕四次歸位，可離線打開 |
| **影片成片** | 約 51 秒 MP4 與 SRT 字幕，畫面動作與字幕對齊 |

做後台示範或單點功能教學都能套用這個套路。案例參考 [《Grok Bot 應用指南實操案例：閒魚上架、小紅書做圖、找工具、做短影片、整理收藏｜Miles Ma》](https://jcng5q8n0f3z.feishu.cn/wiki/TV5UwDLTIiTT4vkpY8qcm33fnSf)。

## 案例 5：收藏整理員（把社媒收藏轉化為選題素材庫）

Miles Ma（@miles_mazy）做此 Bot，把收藏轉成選題庫。

### 操作步驟

1. 側欄新建 Bot，命名「收藏整理員」。
2. 挑 5 類代表連結（如 115 期播客、圖文轉換）。
3. 發送提示詞：

```text
整理這幾條 X 收藏連結，按主題分類，每條留下作者、原連結、核心觀點和可以借鑑的寫法。再圍繞“給新手的 AI 實操課程”提出三個具體選題，做成 Markdown 素材庫和選題清單。
```

4. Bot 整理生成「收藏素材庫」與「選題建議」**兩份 Markdown 文件**。

### 驗收與限制

- 驗收：**保留原作者與原連結**，拆解行文邏輯，3 個選題收斂到單次任務可直接做。
- 限制：**嚴禁將他人實操與資料捏造成親歷**，只學結構思路。

## 案例 6：亞馬遜團隊搭建（從前台巡檢到「1+12」多崗協同）

### 背景與角色定位

- **誰**：Zach（@1999Zach22）。
- **做了什麼**：將原先在本地 Claude/Codex 執行的 Skill 全面遷移至 Grok Bot，在共享雲端電腦上搭建起「1 個出海船長 + 12 個業務崗位」的亞馬遜跨境電商 AI 運營團隊。

### 是什麼

Codex CLI 這類本地工具得一直開機，出門沒法看。**Grok Bot 自帶全天候美國雲端電腦**，手機電腦互通，還能用真實買家帳號在亞馬遜前台瀏覽提問。

Zach 採用 **「1 個船長 + 12 個業務崗位」** 架構。你只對接出海船長，由船長統籌排程各崗位。

**所有崗位嚴格禁止直接改動店鋪後台**，只輸出待批清單供人工確認。

| 崗位 | 負責什麼 | 嚴禁觸碰的邊界 |
| :--- | :--- | :--- |
| 出海船長 | 統籌排程下屬，彙報週報與清單 | 不越過人直接做業務決策 |
| 助理 / 海盜 / VOC | 巡檢跟賣、調研選品與分析差評 | 不登錄賣家後台，不擅自立項 |
| 財務 / 廣告投手 | 測算單品利潤與出具廣告建議 | 絕不登錄後台改出價或加否詞 |
| 文案 / 設計 / 守門員 | 輸出文案、圖片與合規終審 | 不直接發表上線，不替人拍板 |
| 覆盤機器人 | 彙總周產出並更新經驗庫 | 不粉飾運營問題，不編造業績 |

### 怎麼做

#### 1. 訂閱方案與環境準備
- **入門選每月 30 美元 Premium 檔**（8 美元 Plus 檔完全無 Bot），按需升 100 美元 Super 檔或 200 美元 Ultra 檔。
- 電腦手機登錄同帳號，**確認雲端電腦正常執行**。詳見 [Grok Bot 方案與用量指南](https://cursor.com/cn/help/grok-bot/plans)。

#### 2. 先用單 Bot 跑通三件事
用雲端電腦美國 IP 與瀏覽器跑通三項驗證：
1. **自家 Listing 日常巡檢**：查主圖、價格、變體與跟賣，例外帶對比證據彙報。
2. **測試 Alexa 購物問答**：登錄買家號提問，實測約 8 分鐘測完 8 類場景、查 30 天曆史價格。
3. **競品定時盯盤**：記錄價格與優惠券，**變動才發通知**，無變動不打擾。

```text
每天固定時間去前台檢查自家 Listing：主圖和價格是否正確，變體是否正常掛載，核心關鍵詞是否能搜尋到，是否存在跟賣。只記錄指定商品和關鍵詞，有例外才發提醒，並附帶與前一日的對比資料和頁面截圖證據。不登錄店鋪後台，不執行任何寫操作。
```

```text
從消費者的角度，儘可能多地把 Alexa for Shopping 體驗一遍，最後給我一份報告。
```

#### 3. 拆解功能與崗位邊界
- 跑通後將任務拆給 12 個業務崗。
- 廣告與上新等**敏感崗位明文禁止寫入後台**，一律交付「待批清單」，並設清請示邊界。

```text
你是合理燒錢的廣告投手。負責分析廣告效率、搜尋詞轉化率、出價與預算建議。
邊界約束：
1. 絕對不登錄廣告後台，不直接修改出價，不調整預算，不新增否定關鍵詞，不新建廣告活動；
2. 所有優化建議必須生成「待批清單」，每條建議必須附帶調整依據和預期影響；
3. 待批清單單線交付給出海船長，由船長提報給業務負責人審核，嚴禁自主執行。
```

#### 4. 編排「1+N」交接鏈
- **千萬別建多 Bot 群聊**，群聊會重複接收上下文，極速消耗 Token。
- **採用 1+N 架構**，人只對接「出海船長」，由船長派活並收攏結果。

```text
你是出海船長，負責統籌 12 個業務崗位。日常接收業務負責人的目標，拆解為具體子任務派發給對應崗位。所有下屬崗位向你單線彙報，由你彙總結果、審核質量；不達標的打回重做，需要人工決策的整理為帶選項和依據的待批清單彙報給人。嚴格遵守交接鏈規則：
1. 巡檢鏈：助理上報例外與證據，派給資料或廣告崗位做歸因分析；
2. 選品鏈：海盜提交機會報告，財務測算單品利潤，由你整理為立項建議書提報給人；
3. 上新鏈：文案出草稿，設計出圖，守門員審核，你做終檢後交給人確認，由人工在後台發表；
4. 覆盤鏈：收齊各崗位經驗，覆盤機器人寫週報並更新經驗庫，據此編排下週計劃。
所有崗位嚴禁直接登錄店鋪後台或執行未授權的修改操作。
```

#### 5. 資產共用與本地接管
- 所有 Bot **共用同台雲端電腦與磁盤**，指令碼拷入工作區全員可用。
- 讀本地文件需在設定「電腦」頁**打開「在這台電腦上執行」**（Execution on Local Computer）並交代複製目錄。細節見 [Grok Bot 電腦和應用文件](https://cursor.com/cn/docs/grok-bot/work) 與 [Grok Bot 設定說明](https://cursor.com/cn/docs/grok-bot/settings)。

### 可以借鑑什麼

- 先用單 Bot **跑順 SOP** 再拆分。
- 走 **「1+N」主從派發**，防群聊把 Token 跑崩。
- **只出待批清單**，必須人工後台確認。

## 容易踩的坑

- **絕不給賣家後台修改權限**：敏感動作讓 Bot 出「待批清單」由人工執行，防錯標價格或封店。
- **閒魚防腦補成色**：要求「以賣家提供為準，未提供的標待確認」，防混入官網全新參數致退貨。
- **別把 12 個 Bot 拉進一個群**：幾輪對話就耗光整週額度。改用「1+N」主從架構，靠文件落盤中轉。
- **競品抓取以每日 1 次為宜**：幾分鐘輪詢一次極易封 IP 且吃光額度，高頻走官方 API 或 MCP。
- **認準 30 美元/月的 Premium 檔**：8 美元/月的 Plus 沒有 Bot 入口；認準 2026-10-12 起的 The X Subscription。
- **本地接管必須限路徑**：別開始終允許，接管前指定文件路徑並保留彈窗確認，防誤動私人文件。

## 做完怎麼驗收

**交付後對照標準逐項核驗**，別大意。

- **閒魚資料板**：瑕疵與官方參數分列，未知項標「待確認」；嚴禁編自提地址或虛標電池。
- **小紅書圖文**：交 6 張 1080×1440 圖卡與 SVG 原始碼，步驟突出快速鍵及系統前提；別弄亂配色。
- **工具簡報**：單頁 HTML 須帶篩選與官方連結，據實寫明 Docker 環境限制；禁把部署吹成零門檻。
- **教學影片**：成片約 1 分鐘且音畫同步，必須附帶網頁工具原始碼；字幕畫面別脫節。
- **素材庫**：留原作者與原帖連結，選題收斂到單次實操；別空泛總結或把他人案例當自己的。
- **電商協同**：1+N 架構下只對接船長，調價刊登必出待批清單；嚴禁私自改價或死循環耗盡用量。

# 鐵柱的實戰長文與推文

跟做 Grok Bot 最容易踩**三個坑**。
1. 高耗任務全堆給主對話，兩三天燒光整週額度。
2. 雲端電腦一旦重置，環境工具全丟。
3. 多個 Bot 進群循環喚醒，瞬間耗盡用量。

這裡收錄了鐵柱（@cgnot996）的 **9 篇實戰長文與 4 篇系統推文合集**，涵蓋訂閱額度與外部協同、防災備份和架構選型四個主題。每篇都附帶人工摘要卡與直達連結，方便直接照抄提示詞、指令碼與分流方案。

## 訂閱方案與算力額度精打細算

### 額度機制與分流策略

官方按每週共享池計費。**每輪交互都會全量重讀歷史**，直接在主對話貼長文件或長程式碼會讓上下文暴漲，後續每次改動都在重複付費。

**主對話只留關鍵結論與文件路徑**，長資料存進工作目錄，重活分流給後台：
- 寫程式碼交給命令列工具 Grok Build。
- 日常監控交給系統底層定時指令碼。
- 圖片與音影片解析在命令列出純文字摘要後再返回。

日常驗收看兩條指標：
- 每週重新整理日前保留 20% 以上用量。
- **關閉按量付費**，杜絕後台死循環與輪詢空轉。

| 檔位 | 月費 | 建議與額度 |
| :--- | :--- | :--- |
| Plus | 8 美元/月 | 不含 Bot，僅適合輕量開發 |
| Premium | 30 美元/月 | 開啟 Bot 門檻，周額度 4 倍 |
| Super | 100 美元/月 | 高頻排程多 Agent，周額度 15 倍 |
| Ultra | 200 美元/月 | 適合專業團隊，周額度 50 倍 |

把規則發給主力 Bot 即可生效：

```text

```

## 自動化入庫與外部協同網路

### 自動化管道與協同組態

配上 Webhook，Grok Bot 就是 **7×24 小時自動化節點**。

1. Bot 端建例行任務，觸發選“當 Webhook 被觸發時”，保存後獲取介面地址與 Bearer 密鑰。
2. 手機用快捷指令配“獲取 URL 內容”，以 POST 發送 JSON 文字或連結。
3. 微信無分享面板就讀剪貼板；大附件或多圖存臨時網盤換公網連結，Bot 雲端下載解壓。
4. 飛書走長連線，免公網 IP 和自建伺服器，配門鈴觸發器定向派活。

**驗收標準**：
- 手機即發即走不用等。
- Bot 雲端非同步抓取、抽幀轉錄、落庫並給收錄回執。
- 群聊僅被精準艾特或全員時回應。

發提示詞可**自動生成接收端點**：

```text
幫我建立一個 Webhook 觸發的例行任務。快捷指令會用 POST 請求發來一個 JSON，裡面包含一個欄位 info。info 可能是我輸入的文字，也可能是一個文件下載連結，比如微信聊天記錄壓縮包、截圖、錄音。收到後：如果是連結就先下載文件再讀取，壓縮包先解壓；然後整理出要點，收錄進知識庫，最後給我一份回執，寫清楚收錄了什麼、存在哪裡。
```

## 虛擬機器防災與記憶資產備份

### 災備機制與資產分類

所有 Bot 共享同一 Linux 底座（至強 8 核 8 執行緒、16GB 記憶體與 128GB 硬碟，作者自述未核）。**不同 Bot 會話獨立但底層檔案系統打通**，官方無原生匯出。

|場景|保留|丟失與影響|
|---|---|---|
|系統更新|工作目錄與部分憑據|抹掉常駐行程、定時任務與全域包|
|整機重置|無保留|系統盤格式化，非持久化資料全丟|

手動備份不現實，**必須把重建邏輯程式碼化**。災後在新環境跑總入口指令碼，通過健康檢查恢復運轉。

|資產|路徑與文件|恢復策略與坑點|
|---|---|---|
|記憶設定|私有Git：agent-spec.md、profile.md、MEMORY.md|按清單讀入新Bot，還原度約80%（作者自述，未核）|
|常駐服務|私有Git vm-services/：REGISTRY.md、registry.json、原始碼|靠restore-*.sh冪等重裝並通過健康檢查|
|訪問憑證|本地 ~/.agents/secrets/：.env（chmod 600）|**嚴禁進 Git 或記錄**，災後人工按總帳填入|

配給獨立運維 Bot 以下提示詞，維護服務總帳與恢復指令碼。

```text
你是「虛擬機器服務管家」，負責維護這台機器部署的所有第三方服務。你維護一份登記總帳（REGISTRY.md 與 registry.json）、每個服務的獨立恢復指令碼（restore/restore-<服務>.sh，必須冪等可重複執行）、總入口 restore/restore-all.sh，以及一份排除記錄和密鑰的自寫原始碼備份 service-src/。總帳記錄服務 ID、用途、安裝方式、啟停命令、健康檢查命令和密鑰存放路徑。倉庫嚴禁存入明文密鑰。收到恢復指令後，按依賴順序跑指令碼並逐項交出健康檢查驗收清單。
```

## 架構演進、業務實戰與生態選型

### 矩陣分工與選型評估

平時用 Agent 要堅持“一人一崗”。**別把寫程式碼、抓資料，連同生活歸檔與發文全塞給同一個 Bot**，提示詞容易衝突，超長上下文也會把模型帶偏。

平台選型可以參考鐵柱的“品牌整機”與“DIY 組裝機”對比：

| 路線 | 代表產品 | 優勢 | 適用場景與侷限 |
| :--- | :--- | :--- | :--- |
| 品牌整機 | Grok Bot、Muse | 雲端電腦開箱即用，免運維遠端會話與應用整合 | 受官方周額度與規則限制；適合重度依賴社交分發與雲端託管 |
| DIY 組裝機 | 本地開源 Hermes、DS Bot | 自由掛載開源模型，無額度限制，資料高度私有 | 需要自己搭系統、調指令碼；適合純程式碼開發與客製化模型微調 |

業務落地要守住安全與自動化底線：
- 機械性的抓取資料和錄入表格做到全自動化。
- 涉及公開社交運營或資金變動，必須保留人工確認閘門。
- **發文必須走官方 API，嚴禁在雲端電腦裡用無頭瀏覽器模擬登錄**，避免帳號被封。

崗位分工與避坑參考：

| 業務崗位 | 常駐 Bot | 職責 | 安全邊界與避坑組態 |
| :--- | :--- | :--- | :--- |
| 程式碼與運維 | 倉庫管理員、SEO 監控 | 每日監測項目、自動合併 PR、補全指引 | **檢查定時任務日曆**，避免誤設僅工作日執行導致週末停擺 |
| 生活與歸檔 | 記帳管家、知識庫收錄 | 接收快捷指令推送的圖文，錄入多維表格 | 臨時圖床設定高強度隨機 ID，敏感隱私不走公網跳板 |

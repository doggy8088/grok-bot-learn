# 第 10 章 額度與成本：讓一週用量撐滿一週

週二額度用盡、被扣上百美元，常因算力空轉。**Bot 每次喚醒都重讀完整歷史**，幾小時就脹到數十萬 token。

想穩撐一週，做好這三項。
1. 關掉後台按需付費。
2. 減少高頻輪詢與多 Bot 互聊。
3. 收緊會話，少往聊天框塞大文件。

## 扣費原理：額度是怎麼被花掉的

Grok Bot 按模型實際呼叫的 token 計費。**它的核心機制是單會長對話，每次回覆或定時喚醒，都會把全部歷史重新讀取一遍。**

```
每週總消耗 = Bot 喚醒的總次數 × 每次喚醒時重讀的上下文長度
```

會話堆積大量記錄或網頁時，單次重讀可達數十萬 token，回一句也是全量計算。社群拆解見 [《How to Stop Your Grok Bot From Eating a Week of Usage in a Day｜Fan Grok Bot Radar》](https://jcng5q8n0f3z.feishu.cn/wiki/HO20w5OQQiNtNuk92mhcdQEynOi)。

2026 年 10 月 12 日起實行 The X Subscription 統一訂閱方案，各檔位標準如下：

| 套餐檔位 | 個人訂閱價格 | 團隊席位價格 | 額度倍率與 Grok Bot 權限 |
| :--- | :--- | :--- | :--- |
| **Free** | $0 | 不適用 | Limited，不含完整 Bot |
| **Plus** | $8/月（$80/年） | 不適用 | Base，**明確不含 Grok Bot** |
| **Premium** | $30/月（$300/年） | $30/席/月 | 4x，包含 Grok Bot |
| **Super** | $100/月（$1000/年） | $100/席/月 | 15x，包含 Grok Bot |
| **Ultra** | $200/月（$2000/年） | $200/席/月 | 50x，包含 Grok Bot |

額度規則詳見 [Cursor 官方指南：方案和計費](https://cursor.com/cn/help/grok-bot/plans)，日常使用有幾處硬性限制。

- **額度池不疊加**：多檔訂閱只取每週額度最高的一方，不合並累加。
- **共享池範圍**：每週額度覆蓋 Grok Bot 和 Cursor 裡的 Grok，也包括網頁端、手機端、Imagine 與 Voice，到期固定重置。
- **第三方模型單獨計費**：在 Cursor 內呼叫非 Grok 模型直接按量計費。
- **按需付費與月度限額**：周額度耗盡後開 On-demand 計入月度限額（Monthly Limit），超出限額任務也會跑完；關掉則停止回應等待重置。

**官方明確沒有模型選擇器（there is no model picker），無法切到低配模型。** 控制成本只能降低喚醒頻率、截斷上下文長度，或把高耗計算分流到外部。

## 高耗操作清單：堅決避開的六大陷阱

參考出處：[《4.1 額度與成本：省額度清單》](https://jcng5q8n0f3z.feishu.cn/wiki/KFbzwPhAliezlBkkvIuc1Abgn4h)、[《Grok Bot 額度超長續航保姆級新手指南（直接發給 Bot！）》](https://jcng5q8n0f3z.feishu.cn/wiki/OPMJw2EgtiWMiJkcrzFc6gJ8nlf)。

| 高耗操作 | 費額度原因 | 避坑做法 |
| :--- | :--- | :--- |
| 多 Bot 群聊 | 互相喚醒導致 token 翻倍空轉 | 單主導 Bot 配 Subagents 派活，或人工單聊 |
| 對話直接喂圖與影片 | 歷史幀常駐，每輪全量重讀買單 | 終端命令列處理，Bot 只接百字內結構化文本 |
| 全天高頻輪詢 | 15 分鐘一次每週 672 次，多在確認無變動 | 收緊到工作時間，或改用系統指令碼加 Webhook |
| 一條會話用到底 | 數十輪後單輪重讀數十萬 token | 單任務單會話，定期總結並 Duplicate 重置 |
| 無保護重試死循環 | 報錯後連續自我嘗試數十次 | **提示詞強制設 2 次重試上限**，失敗立刻阻斷問人工 |
| 盲目開按量付費 | 死循環可能一夜產生高額帳單 | **平時關閉按需付費**，開啟必須設嚴格低額月度上限 |

## 省額度四步工作流：從止損到分流

### 鎖定計費與安全底線
1. 進 Settings > Usage & Billing 核對套餐（Premium $30/月 或 Super $100/月）、用量與倒計時；卡住點 Stop 強制結束。
2. **除錯時關 Additional Usage / On-demand**；若開，去 cursor.com/dashboard > 支出 > Monthly Limit 設月限額（$10-$20）。
3. 進 Settings > General > Auto-review，**把 send、post、buy、transfer、delete、permissions 設為 Ask first 人工批准**。

### 規範會話與交互
- **單任務單會話**，做完立即歸檔。
- 記錄長文存進 `/workspace/`，只回結論和路徑，嚴禁貼回。
- X 搜尋限每分 30 次、每天 1000 次（不扣周額度），**約束 Bot「提取核心事實，以 3 到 5 條要點輸出」**。
- 會話臃腫時用 Duplicate 重置，先讓舊 Bot 寫 10 行內總結，複製發給新 Bot 接手，隱藏舊 Bot。

### 能力路由與分流
- 主 Bot 只負責拆解、派發與彙總，不寫長程式碼或轉大文件。
- **寫程式碼走 Cursor 雲端 Agent**（走 Cursor 額度不扣周額度），或在虛擬機器無頭跑 Grok Build CLI / Codex CLI。
- 截圖與音影片由雲端電腦命令列處理，或用免費模型轉文字再餵給 Bot。

### 定時任務改造
1. Details > Routines 裡，**暫停或刪除過去一周天天報「沒有變化」的例程**。
2. 換 Linux 指令碼低成本輪詢，有變動再發 Webhook 喚醒 Bot。
3. **保留例程寫入靜默指令**：「檢查後若無變化，直接結束任務，嚴禁輸出任何文字」。

參考：[《4.1 額度與成本：省額度清單》](https://jcng5q8n0f3z.feishu.cn/wiki/KFbzwPhAliezlBkkvIuc1Abgn4h)

## 例程與輪詢深度優化：告別無效空轉

例程是隱蔽的額度黑洞，高頻輪詢**一天就能用掉整週用量**。

### 頻率收斂與執行窗口控制

客戶端先核對 Bot 的 Timezone 是否與本地一致。不同排程設定消耗如下：

| 排程設定 | 每週執行次數 | 適用場景 |
| :--- | :--- | :--- |
| 每 15 分鐘一次（全天候） | 672 次 | 極易在 1 到 2 天耗盡額度，極少需要 |
| 每小時一次（全天候） | 168 次 | 關鍵基礎設施故障監控 |
| 工作日 9:00 至 17:00 每小時一次 | 45 次 | 看板追蹤、工單處理與郵件分揀 |
| 每個工作日 3 次 | 15 次 | 每日收件箱早中晚初篩、進展跟進 |
| 每週 1 次 | 1 次 | 行業週報、技術動態總結與文件歸檔 |

限定工作時間可用標準 cron 格式：

```text
CRON_TZ=Asia/Shanghai 0 9-17 * * 1-5
```

**這行規則把喚醒量降低了 93%**。在上海時區工作日 9:00 至 17:00 整點執行，一週僅觸發 45 次。

### 指向技能並嚴格執行沉默規則

例程提示詞只指向技能，不展開細節：
- 斜槓命令指定具體技能名與檢查物件
- 給出判定閾值、停止條件與單次重試限制
- **無變化時保持完全靜默，不發任何訊息**

純靜默容易掩蓋中途故障。搭配方案參考[Cursor 官方指南：例程](https://cursor.com/cn/help/grok-bot/routines)：高頻例程保持靜默；低頻例程每天 18:00 發單行心跳記錄，確認過去一天正常執行。

### 雙角色分離：Linux cron 指令碼巡檢加 Webhook 喚醒

Bot 休眠時底層 Linux 雲端電腦還在執行，**別讓大模型去幹機械比對**。
- 檢查角色：系統自帶 cron 排程 Python 或 Shell 指令碼比對，耗時幾秒，消耗額度為零。
- 判斷角色：指令碼檢測到變動再發 Webhook 喚醒 Bot 進行邏輯判斷與報告。

Webhook 喚醒步驟與驗收標準：
1. 在例程 Webhook 區域獲取 `POST to` 地址與 `key`。
2. 向該 URL 發送帶有 `Authorization: Bearer <key>` 頭的 POST 請求。
3. 檢查回應狀態碼，返回 200 即代表喚醒成功。

### 實戰案例與避坑

- **鐵柱改造行銷總監 Bot 的 6 條例程**：4 條交付類例程保留不變；2 條純等回覆與審 PR 的空轉任務換成系統 cron 指令碼加 Webhook。指令碼工作日白天每半小時檢查一次，有新變動才喚醒。**改造耗時約 23 分鐘，每週減少 8 到 10 次多餘喚醒**，新動態發現速度提到了半小時內。案例出處：[《Grok Bot 額度再省一點：定時任務極限優化》](https://jcng5q8n0f3z.feishu.cn/wiki/SDr3wRrG5iGmz1kejdTcss0Rned)。
- **Craig Hewitt 24 小時燒光 Ultra 周額度**：訂閱每月 $200 的 Cursor Ultra 套餐，2026 年 8 月 23 日一天耗盡整週額度。他在日常主聊的主管 Bot 上歸檔 10 年舊郵件，介面拉取正文不斷追加到會話，上下文脹到幾十萬 token 引發全量重讀風暴。案例出處：[《How to Stop Your Grok Bot From Eating a Week of Usage in a Day｜Fan Grok Bot Radar》](https://jcng5q8n0f3z.feishu.cn/wiki/HO20w5OQQiNtNuk92mhcdQEynOi)。
- **高負載避坑要點**：**高負載一次性任務絕不能放在天天聊的主 Bot 上**，必須新建專用 Bot 或通過 Duplicate 生成副本；處理前先用郵箱規則過濾垃圾郵件；批量任務必須先拿 1 到 2 個樣本驗證無誤後再啟動。

## 群聊與多 Bot 控制：杜絕互相喚醒

**千萬別把多個 Bot 拉進同一個群聊。** 新訊息會全員廣播，每個 Bot 都會重讀全量歷史並回復。鐵柱自述 4 個 Bot 互聊迅速吃掉了 25% 周配額（未核）。

多 Bot 協作要堅持**中心輻射、禁止橫向串聯**。

- 唯一主導：只保留一個主導 Bot 作為交互入口。
- 單向派活：主導 Bot 啟動 Subagents 或 A2A 單點交接，子智慧體跑完自動退出，不在群裡接話。
- 成果落盤：上游把資料寫入 `/workspace/` 下的文件，下游直接讀取，不在聊天框推敲。
- 清理閒置：確認無掛載例程後及時刪除閒置 Bot，防止被誤喚醒。

## 用量審計與應急機制：守住每週節奏

### 每週 15 分鐘審計流程

建議在每週重置日前一天花 15 分鐘核查：
1. 打開 Settings > Usage & Billing 查看已用百分比。若消耗超前，調出前幾天任務定位例外日期。
2. 進入 Details > Routines 查看近 20 次執行記錄（Running、Succeeded 或 Failed），排查報錯重試或頻繁空轉的例程。
3. 針對 v0.66.0 起的星標主 Bot，**在描述中明確禁止主動接活**，防它自行攬下瑣事。
4. 訪問 cursor.com/dashboard，核對 Monthly Limit 與實際按需扣費，確認無例外扣款。

### 監控盲區與應對

系統不提供單個 Bot、例程、會話或模型的消耗明細，20 條執行歷史也不記錄 token 和金額。**測試新流程必須採用控制變數法**：
1. 每次只新建或修改一個 Bot 或例程。
2. 執行前後各查一次 Usage & Billing 的百分比對比增量，切忌同時上線多個新例程。

### 額度耗盡時的雲端電腦接管應急

周額度 100% 耗盡且前端對話鎖定後，底層的 Linux 雲端電腦並沒有銷燬，通過客戶端打開桌面或系統終端即可接管：
1. 查看 `/workspace/` 目錄下未交付的程式碼與文件。
2. 手動執行 `git commit` 和 `git push` 推送到遠端倉庫。
3. 用本地命令列工具在終端接替除錯，**絕不需要花錢購買附加用量**。

## 直接發給 Bot 的省額度提示詞庫

### 上下文防膨脹
- 規則讓 Bot 提煉寫入 Description，**省去聊天重複交代**。
```text
請回顧我們至今的協作流程，執行兩項沉澱工作：
1. 把你需要長期遵守的行為邊界、彙報格式與約束規矩，提煉成一段不超過 300 字的精簡文本，我將直接粘貼到你的描述（Description）中；
2. 把我們剛才已經跑通的標準操作流程，封裝為一個可複用的技能（Skill），供後續例程直接呼叫。
完成提取後直接在對話中給出文本，不要展開多餘閒聊。
```
- 原始記錄與長資料強制存盤，不直接貼進會話。
```text
從現在起執行上下文瘦身規則：
所有抓取的長篇網頁、介面除錯記錄、大批原始資料和階段性中間產物，一律直接保存為 /workspace/ 目錄下的文本文件。在聊天視窗中回覆我時，嚴格只提供核心結論、關鍵變動要點以及對應的文件絕對路徑。嚴禁將大段原始文本或記錄程式碼貼回對話。
```
- 多模態圖片轉命令列解析，**避開聊天框高消耗**。
```text
遇到查看多張截圖、分析影片畫面、逐幀拉片、音訊轉寫或處理長掃描件的任務時，嚴禁在當前對話框中直接讀取原始多模態文件。
你應當在雲端電腦終端中呼叫系統已組態的命令列工具（如 Grok Build 或相關轉錄 CLI）在後台執行，並輸出簡明的結構化文字摘要；你只需閱讀生成的文字結論。如果當前環境無法執行命令列解析，請停下提醒我先在網頁端轉換成文字後再發給你。
```

```text
請協助組態 OpenRouter 免費模型呼叫環境，嚴格遵循以下安全執行流程：
1. 在聊天框中調出系統的密鑰輸入彈窗向我收取 API Key，嚴禁讓我把密鑰明文發送在普通對話中；
2. 將獲取到的 Key 保存到 ~/.agents/secrets/openrouter.env 文件中，環境變數名指定為 OPENROUTER_API_KEY；
3. 對該密鑰文件執行 chmod 600 設定安全權限；
4. 執行全程嚴禁在終端標準輸出或聊天訊息中打印該 Key 的明文內容；
5. 使用 curl 呼叫一個以 :free 結尾的免費模型進行一次最小文本測試，確認呼叫成功且費用為 0，並將測試結果告訴我。
```

## 容易踩的坑

- Details > Routines 點選 Test 會跑真機流程，**每次都扣真金額度**。
- Cursor 與 SuperGrok **額度不累加**，只算周用量高的一方，另一方閒置。
- grok.com 與 Grok Bot 計費獨立，網頁版儲值**不能抵扣且不退款**。
- 聊天框貼 API Key 或 Webhook 佔 token 且危險，**必須用安全彈窗寫環境變數**。
- 點「更新電腦」會抹掉 Linux cron，`/workspace/` 保留，**更新後得重裝 cron**。
- Duplicate 會丟棄對話、learned memory 與附件，**得手動給新 Bot 喂上下文**。
- Monthly Limit 觸發後不殺行程，**長任務會跑完**，死循環可能超額。

## 做完怎麼驗收

1. 進 Settings > Usage & Billing 和 cursor.com/dashboard 查帳單，確認看到已用百分比與重置倒計時，**關掉 Additional Usage 或把 Monthly Limit 設在安全低位**。
2. 讓 Bot 模擬刪文件或對外發網路請求，必須彈出 **Ask first** 審批卡片並掛起等待，絕不能靜默執行。
3. 檢查當前會話並下發多推文 X 搜尋，側邊欄不留數十輪長會話，只返回 3 到 5 條簡報，長文本落盤至 `/workspace/`，對話框不刷原文。
4. 去 Details > Routines 給無變動的監控例程點 Test，檢查後直接靜默退出，不發多餘的「無更新」閒聊。
5. 讓 Bot 編寫多文件依賴程式碼，看它在後台呼叫 Grok Build 或雲端 Agent，**只輸出最終狀態與執行摘要**，聊天框不貼整屏程式碼。

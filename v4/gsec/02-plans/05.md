## 老訂閱切換決策與操作指南

### 是什麼

The X Subscription 統一大訂閱在 2026 年 10 月 12 日上線。手頭有老訂閱的使用者，官方給出了兩套處理規則。

不主動切換的使用者，原有套餐方案、價格與功能全部維持現狀不變。年付週期會完整保留到自然到期，後續若有變動也會提前通知，且變動只在續訂時生效。

如果確認切換，**操作在網頁端一旦確認完成便永久生效，聯繫客服也無法撤回或恢復老套餐**。系統結算時會自動終止舊訂閱，未消耗的時間按天折算退款至原支付方式，這筆錢不能抵扣新套餐，新套餐需要全額支付，新的帳單週期從當天重新計算。此外，切換操作必須在網頁端進行，手機客戶端目前不支援。

不同支付渠道在切換時的退款規則差異明顯，處理不當容易造成重複扣費。

| 支付渠道與訂閱產品 | 切換時的處理方式 | 退款途徑與使用者操作 |
| :--- | :--- | :--- |
| **網頁端直接購買的各種舊方案** | 結帳時系統自動取消舊訂閱 | 官方自動按比例退款到原支付卡，無需額外人工操作 |
| **Apple 渠道訂閱的 Grok / X Premium** | 系統自動向 Apple 發起取消申請 | 官方協助提交，由 Apple 最終決定退還金額 |
| **Apple 渠道訂閱的 Cursor** | 官方無法代為取消，也無法代為退款 | **使用者必須親自前往 iOS 系統的「Apple ID → 訂閱」手動取消，並向 Apple 客服申訴退款** |
| **Google Play 渠道訂閱的各項服務** | 系統切換後不會自動解約 | **使用者必須在 Google Play 的「支付和訂閱」中手動取消自動續訂** |

### 實戰案例：社群作者面對大一統訂閱的決策實錄

社群開發者鐵柱AGI（@cgnot996）長期使用 Grok Bot 與 Cursor 處理程式設計與自動化發表，手裡有一份有效期至 2027 年的年費方案（作者自述，未核）。大訂閱上線後，他全面排查了用量，決定**暫時不把手裡的老訂閱切換為新版大一統訂閱**，同時關閉原方案的自動續費，繼續持有老權益觀望。

他主要排查了三項指標：

1. **核對個人帳單優惠與年付沉沒成本**。老方案帶有長期優惠，強行切換新方案已享有的優惠直接作廢。
2. **核對第三方模型呼叫依賴度**。老套餐附帶第三方模型額度；新方案每週共享池只覆蓋自家模型，所有第三方模型呼叫都得按 API 標價另行掏錢。他日常程式設計重度依賴第三方模型輔助審查，切換後單月總支出會大幅增加。
3. **權衡共享池機制的影響**。老套餐中 Grok Bot 與其他產品額度分開計算；新方案每週用量池共享，Bot 跑多了容易擠佔網頁端與程式碼補全的正常額度。

| 人群分類 | 典型特徵與核心訴求 |
| :--- | :--- |
| **建議換的人群** | 原先單獨購買多個零散訂閱、每月開銷遠超 30 美元；主要使用官方模型、很少呼叫第三方模型；對 Grok Bot 自動化與 X 帳號運營有強捆綁需求。 |
| **不建議換的人群** | 手裡持有包含額外第三方模型額度的舊方案；只在 Cursor 裡重度寫程式碼、對 X 社交權益與影片生成完全不感興趣。 |

從實操中可以總結出三條避坑原則：

- 決定切換前，先打開用量面板查看真實的呼叫分佈，摸清自家模型與第三方模型的比例。
- AI 工具儘量按月訂閱，套餐政策兩三個月就會重組，一次性鎖定長週期年費容易陷入被動（作者自述，未核）。
- 涉及應用商店的訂閱必須親自清理後台。**通過 Apple 訂閱過 Cursor 的使用者，決定遷移後必須在手機後台手動取消自動續訂**，網頁端升級不會代為處理。

### 做到什麼程度算好

保留老方案的使用者，需確認自動續訂狀態符合預期，核心模型額度完好。

**決定切換新方案的使用者，需確認舊訂閱已徹底解除且原渠道收到退款，新方案按 Premium 正常計費，兩端沒有出現重複計費或通道衝突。**

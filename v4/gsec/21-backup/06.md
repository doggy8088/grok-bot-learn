## 21.1 認清雲端電腦的底細：更新、恢復與重置有什麼區別

**同一帳號下所有 Bot 共用同一台虛擬機器**，共享 `/workspace` 目錄與系統行程。一台機器裝了全域工具其他 Bot 都能調，機器一旦重置，所有依賴環境會同時失效。參考 [《4.6 虛擬機器、記憶與備份》](https://jcng5q8n0f3z.feishu.cn/wiki/KUggwkhqqiRyxZkwTLhcrCU2ncg)。

客戶端在 **Settings** > **電腦** 的 **Bot's 電腦** 下提供控制項。三者區別如下：

| 操作 | 機制 | 保留內容 | 丟失內容 |
| :--- | :--- | :--- | :--- |
| **更新（Update）** | 升級環境鏡像。分軟體更新和電腦更新兩類 | 軟體更新保留全部；電腦更新保留機器人、文件與登錄資訊 | 軟體更新無丟失；電腦更新移除全域應用和軟體套件 |
| **Recover** | 基於已存資料在最新鏡像建新機，先嚐試連線舊機存資料 | 已保存的機器人、文件與登錄資訊 | 全域應用和軟體套件；若舊機連不上，未同步的修改會丟 |
| **Reset** | 直接按最近保存的資料建新機，中斷正在執行的工作 | 已保存的機器人、文件與登錄資訊 | 全域應用和軟體套件；未同步的修改會丟 |

對話記錄存在雲端，機器重置或誤刪文件都不影響。但**全域安裝的應用包、`node_modules` 與 Python 虛擬環境不會被官方保存**，遇到電腦更新、Recover 或 Reset 都會被清掉。詳見 [《Grok Bot 電腦》](https://cursor.com/cn/help/grok-bot/computer-recovery)。

虛擬機器卡死或回應例外時，排查要按順序來：

1. 顯示 **Reconnecting** 或 **Couldn't Reach Grok Bot's 電腦**：屬於網路波動，稍等後點 **Retry**。重連期間文件不丟，**嚴禁在這個階段點 Reset**。
2. 重啟客戶端。Mac 使用者必須在頂部選單欄選 **Quit**，單純點窗口紅叉無效。
3. 檢查更新。進 **Settings** > **電腦**，有可用更新先點 **更新**。提示智慧體未暫停就等當前任務跑完再點。
4. 嘗試恢復。依然連不上或更新卡住出現 **恢復電腦** 時點 **Recover**。若提示 **Update 仍在執行**，選 **Keep waiting**。
5. 執行 **Reset**。前四步無效再點 Reset。失敗可用 **Retry Recover** 或 **Retry Reset** 重試，繼續報錯聯繫官方支援。
6. 處理磁盤告警。收到 **Computer is low on disk space** 或 **Computer is critically low on disk space** 時別手動刪文件，點側邊欄 **Go to Disk Saver** 查看方案，未經確認系統不會刪文件。詳見 [《Grok Bot 電腦》](https://cursor.com/cn/help/grok-bot/computer-recovery)。

**雲端電腦只是一次性容器**，不要手動微調環境。搭建過程全部指令碼化，組態與自寫原始碼必須存進外部私有 Git 倉庫。

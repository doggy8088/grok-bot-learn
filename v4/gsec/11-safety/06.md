## 網路策略與邊界收攏

### 核心權限
**連線器策略與網路策略完全獨立**。後台禁用外掛管不住 Bot 調自帶瀏覽器訪問公網。**網路控制（Network Controls）僅限企業版**，Teams 方案預設全通且無組態面板，需在 Cursor 儀表盤進 Grok Bot > Network > Grok Bot Network Access 組態。

### 訪問模式
| 模式 | 生效規則 | 適用場景 |
| :--- | :--- | :--- |
| **Allow All Network Access** | 允許訪問所有公網目標（預設狀態） | 探索性研發、無敏感資料業務 |
| **Defaults + Team Allowlist** | 放行系統基礎域名加團隊自訂列表 | 絕大多數企業正式環境 |
| **Team Allowlist Only** | 僅放行自訂列表與維持虛擬機器底線 | 嚴苛的合規審計環境 |

支援網頁域名與原始 TCP 的 IP 範圍及端口，條目數量沒有上限。正在執行的電腦約一分鐘內自動同步，休眠機下次喚醒時應用。目錄群組策略優先於團隊策略，開啟全域鎖定（Lock）則全員生效。

### 避坑與私網
- 共享靜態出口 IP 為全體客戶共用，**絕不能用來標識具體團隊**。內網需要放行時向帳戶團隊索取最新 IP 段。
- 網關放行 `api2.cursor.sh` 卻解密巢狀 (Nesting)域名會導致機器卡在 Setting up computer，**須在所有 profile 中將 `*.cursorvm.com` 與 `*.*.cursorvm.com` 加白並跳過證書解密**。參見[組態 TLS 檢查代理](https://cursor.com/cn/docs/grok-bot/proxies)。
- 訪問內網資源可開啟桌面端流量轉發（Allow Local Egress Routing），或用團隊環境設定指令碼（Team Setup Scripts）在初始化時統一安裝 VPN 客戶端。參見[連線到私有網路](https://cursor.com/cn/docs/grok-bot/private-networks)。

### 做到什麼程度算好
- **明確封鎖非必要外網請求**
- 阻斷未經允許的文件外發傳輸
- 內網網關正確放行巢狀 (Nesting)域名，無虛擬機器連線掛死現象

## 交接文件約定：以共享檔案系統替代對話歷史

別讓 Bot A 在聊天窗貼結果再給 Bot B 讀。**窗口交互會快速撐爆上下文且容易丟失歷史**，各 Bot 對話在底層邏輯隔離，根本沒法互相檢索。

| 維度 | 特徵與包含內容 |
| :--- | :--- |
| **物理共享層** | 同帳號下所有 Bot 共用虛擬機器、`/workspace` 目錄、連線器與公共 Skill 庫。 |
| **邏輯隔離層** | 對話歷史互不可見，Bot A 無法調取 Bot B 與使用者的私人對話。 |

物理磁盤既然共享，傳遞任務就靠本地結構化文件，對話框只用來同步狀態與路徑。

### 文件交接流水線標準

標準交接包含落盤、傳路徑，再到讀取與歸檔。

```
[使用者指令] ──> (主排程 Bot)
                   │
         1. 派發任務 (指定輸出路徑)
                   │
                   ▼
             [專職 Bot A] ──> 寫入 /workspace/proj/data.json
                   │
         2. 交付：僅返回文件絕對路徑
                   │
                   ▼
             (主排程 Bot)
                   │
         3. 排程下發 (附帶輸入路徑)
                   │
                   ▼
             [專職 Bot B] ──> 讀取 data.json ──> 寫入 output.md
                   │
         4. 彙總簡報至使用者
```

1. **任務派發**：主 Bot 明確指定交付絕對路徑，如 `/workspace/project-alpha/data.json`。
2. **資料落盤**：專職 Bot A 跑完清洗寫入文件，在對話框只回一句話通知保存路徑。
3. **路徑傳遞與讀取**：主 Bot 喚醒 Bot B 並傳遞路徑，Bot B 讀盤分析後把結論寫入 `/workspace/project-alpha/report.md`。
4. **交付呈現**：主 Bot 提煉摘要，附上本地或雲文件連結供審查。

推文畫像流水線也是這套模式，整理員抓取存入 `tweets.md`，分析師讀文件提煉標記寫入 `profile.md`，設計師輸出 `design.md`，工程師據此寫程式碼並給預覽截圖。實操參考 [《4.2 團隊編排：章程、崗位與放權》](https://jcng5q8n0f3z.feishu.cn/wiki/POTrwwThoiQxIakFDIDcUcKjnmh)。

### 接入飛書雲文件實作可追溯交付

需要團隊協作或批註時，給虛擬機器配飛書 CLI 把 Markdown 發為雲文件。它自帶獨立連結方便分發，支援逐段批註，也能**保障企業資料安全**。

工作流達標包含這幾項要求：
- 鏈路中每個 Bot 都能獨立讀寫 `/workspace` 下的固定文件。
- **對話框只傳輸狀態提示與文件絕對路徑**。
- 出現例外時，檢查對應磁盤文件即可復現定位。

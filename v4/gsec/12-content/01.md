## 自媒體團隊的崗位設計與協作機制

### 是什麼

**在 Grok Bot 搭團隊，核心是「單崗單責」。** 帳號下所有 Bot 共享同一台雲端電腦（擁有獨立內核、記憶體和 `/workspace` 路徑），但各自擁有獨立的窗口、記憶與設定。Bot 之間靠在共享資料夾讀寫 Markdown 文件交接任務。

### 怎麼做

**主 Bot 頭像帶星標（右鍵頭像可切換）**負責統籌派工，5 到 6 個專職 Bot 嚴格按職責邊界工作。

| 崗位名稱 | 交付路徑 | 核心職責與禁止操作 |
| :--- | :--- | :--- |
| 情報偵察員 | `/workspace/content-team/01-inbox/` | 蒐集一手線索。嚴禁互動發文與私信，嚴禁把二手言論當事實 |
| 選題策劃師 | `/workspace/content-team/02-briefs/` | 評估線索出 Brief。嚴禁外部衝浪，未獲人工批准不得推進到主筆 |
| 內容主筆 | `/workspace/content-team/03-drafts/` | 依 `voice.md` 寫作。嚴禁捏造事實與通用公關腔 |
| 事實編輯 | `/workspace/content-team/04-review/` | 核驗一手信源。無發表權限，證據衝突列出待確認 |
| 資料覆盤師 | `/workspace/content-team/06-analysis/` | 分析內容資料。嚴禁帳號互動，嚴禁將相關性寫成因果，缺資料嚴禁硬猜 |
| 網站工程師 | `/workspace/tweet-portrait/` | 提煉畫像建站。嚴禁偽造經歷，嚴禁把本地路徑當公網連結 |

1. 在雲端電腦終端建立標準共享目錄。
```text
/workspace/content-team/
├── 00-profile/     # 帳號定位、目標讀者、範文、禁用表達（voice.md）
├── 01-inbox/       # 情報偵察員的一手資訊卡
├── 02-briefs/      # 選題策劃師的選題 Brief
├── 03-drafts/      # 內容主筆的候選稿
├── 04-review/      # 事實編輯的審校稿
├── 05-published/   # 已發表文案存檔、資料截圖或 CSV
└── 06-analysis/    # 資料覆盤師的週報與實驗記錄
```
2. 在 `00-profile/voice.md` 寫入風格基座，避免主筆產出套話。
```text
# 帳號定位
- 我長期寫：面向個人創業者與開發者的 AI 工具實測與提效工作流
- 我的目標讀者：正在用 AI 嘗試做獨立產品、做內容或做業務轉型的實幹者
- 讀者看完後應該獲得：直接能照著執行的步驟、準確的參數組態、明確的避坑提醒

# 寫作樣本
- 代表作 1：【粘貼一段自己資料最好、語言最順的代表作】
- 代表作 2：【粘貼一段帶步驟拆解的課程代表作】

# 表達習慣
- 常用語氣：像跟坐在對面的朋友覆盤經驗，冷靜、直白、短句為主
- 禁用表達：我的判斷是、毫無疑問、重塑格局、顛覆行業、進入新時代、不難看出
- 不會公開談論的內容：未經實測的空頭八卦、無法復現的玄學跑分

# 商業與事實邊界
- 必須保留原始來源的主張：所有關於產品上線、價格變動、官方改版的陳述
- 未親測時的寫法：必須明確標明“未核實”或“作者自述”
```
3. **建群分發規則**。點選「新建聊天」建立「自媒體內容團隊」群聊並拉入全員。初次切忌直接指派選題，必須先發統一規範。
```text
這是“自媒體內容團隊”協作群。工作順序固定為：情報偵察員 → 選題策劃師 → 內容主筆 → 事實編輯；內容發表後，資料覆盤師讀取授權資料 → 06-analysis。所有中間文件放到 /workspace/content-team/ 對應目錄。任何登錄、外發、發表、按讚、回覆、關注、私信、購買、刪除、連線器授權或權限修改都必須先獲得使用者明確批准。本次僅確認收到和各自交付路徑，不執行外部操作。
```

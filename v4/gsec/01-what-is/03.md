## 適合與不適合的任務型別

### 任務過濾標準
**任務該不該交給 Grok Bot，直接看三條過濾標準**：
- 能在網頁端、終端或通過 API 完整跑通；
- 中間文件或最終報告能由人工直接核驗；
- 高危敏感動作能停下來等人工彈窗批准。

### 適合的任務
**適合流程固定、高頻重複且需跨工具呼叫的活**：
- **情報巡檢**：定期訪問固定官網、Changelog 或社媒出摘要表。
- **線索清洗**：CRM 撈目標帳戶，結合公開資訊起草外聯信供審核。
- **財務對帳**：每週核對發票，標記缺票並催收。
- **缺陷復現**：讀 Issue 在預發表環境模擬復現，提取記錄與截圖。
- **經營晨報**：每天彙總庫存、訂單與流量指標，揪出例外點。

### 不適合的任務
**別硬塞不匹配的活，容易白耗每週額度甚至失控**：
- **即時問答**：查報錯、翻短文用普通網頁模型幾秒搞定，不用雲端電腦。
- **本地寫碼**：中斷點除錯與 Git 衝突放本地 Codex CLI 或 Claude Code；一澤提醒其上下文有限，更適合調研驗收而非純寫程式。
- **生活瑣事**：管日曆、買日用品缺乏企業級資料源，硬搬很彆扭。
- **無增量輪詢**：每 5 分鐘無條件重新整理會空耗推理額度。
- **高危操作**：群發郵件、對外發文、扣款支付或刪庫，必須留人工閘門。

## 典型實戰案例拆解

### 金塵馬的情報總監（個人調研崗位）

金塵馬（@jinchenma_ai）搭建了一個追蹤前沿動態的數位員工。

1. 在 Edit Profile 的 Description 中寫明長期崗位規則，定性為情報調研員。
2. 用五要素（結果、來源、限制、格式與確認點）派單，檢索 X 平台長文並區分影片帖，標明曝光資料，無一手資料嚴禁編造。
3. 首次交付糾偏格式後，發指令要求 Bot 把流程**沉澱為 Skill**「AI 課程情報蒐集」。
4. 換第二組輸入測通後組態 Routine，定在每個工作日早上 8:10 自動執行並彙報。
5. 新建「內容總監」負責選題評審，初稿保存到 `/workspace/grokbot-demo/` 供讀取。

**崗位說明沉澱長期規則，臨時需求走訊息**，多 Bot 協作通過 `/workspace` 落盤解耦。實操細節見[《萬字長文｜Grok Bot 從入門到精通｜金塵馬》](https://jcng5q8n0f3z.feishu.cn/wiki/MIKpwiUXpiE9mWkyG8ccFM6Znee)。

### 金塵馬的電商運營團隊（多角色分工流水線）

金塵馬（@jinchenma_ai）把單兵模式升級成了 4 個 Bot 的協同流水線。

1. **單點起步**：建「店鋪經營值班員」讀商品表、庫存表和訂單表發晨報。**卡死唯讀紅線，嚴禁改價、改庫存、發信或退款**。
2. **細化拆崗**：拆出「內容增長專員」（分析流量與選題）、「商品與庫存分析員」（盯缺貨與週轉）和「訂單與售後例外助理」（查履約並草擬回覆）。
3. **協同流轉**：原值班員升級為「電商運營主管」，各崗位將資料保存至 `/workspace/ecommerce-ops/日期/` 目錄。
4. **業務聯動**：庫存分析員發現爆款僅剩 3 天庫存，內容專員暫停推廣，售後助理備好延期話術，主管彙總決策清單。

不要一上來就搭建龐大團隊，**涉及資金、庫存與外部發信的操作全部鎖定人工審批**。

### 鐵柱的開源倉庫管理員 Bot（自動化運維巡檢）

鐵柱AGI（@cgnot996）搭建常駐 Bot 自動維護 awesome-grok-bot 知識庫。

1. **組態巡檢**：定期掃描 X 平台公開推文、官方更新記錄與技術社群動態。
2. **分類提交**：把新玩法、課程、官方文件和線下活動結構化分類並自動收錄。
3. **實際效果**：作者公開宣發前已自動收錄相關資料；2026 年 8 月突破 130+ Star（作者自述，未核），並獲得官方人員的申請表單邀請。

常駐 Agent 很適合承擔**長效資料檢索與文件歸檔**，能把人從重複的資訊蒐集裡解脫出來。

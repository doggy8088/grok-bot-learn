## 21.2 虛機服務總帳與自動化恢復流水線

Grok Bot 不給虛機快照權限，**把重建步驟寫成 Git 冪等指令碼成本最低**。參考 [《4.6 虛擬機器、記憶與備份》](https://jcng5q8n0f3z.feishu.cn/wiki/KUggwkhqqiRyxZkwTLhcrCU2ncg)。

### 服務總帳與原始碼防汙染

私有倉庫建一個 `vm-services/` 目錄，`REGISTRY.md` 給人看，`registry.json` 供指令碼解析。自寫指令碼單獨存進 `service-src/`。

總帳登記服務 ID（如 `wechat-crawler`）、負責 Bot、路徑以及啟停檢查命令。**憑證只填絕對路徑（如 `~/.env`），絕不明文記錄**，人工掃碼或 OAuth 認證需高亮。

推送自寫程式碼前排除 `venv/`、`.env/` 和 `node_modules/` 等目錄與快取記錄，**commit 前跑指令碼正則掃描防洩漏**。

### 自動化恢復流水線

在 `vm-services/restore/` 為各服務編寫 `restore-<服務名>.sh`，**指令碼必須保證冪等，重複跑不報錯**。

總入口 `restore-all.sh` 按固定依賴順序串聯六個執行層。
1. **系統依賴**：安裝 `cron`、`ffmpeg` 和 `yt-dlp` 等底層工具。
2. **原始碼就位**：從 `service-src/` 拷回自寫指令碼，跳過已有目錄只補缺失。
3. **語言環境**：建立虛擬環境並執行 `pip install -r requirements.txt`。
4. **常駐行程**：拉起介面代理與後台轉發。
5. **系統排程**：讀取 crontab 恢復定時任務。
6. **健康檢查**：跑核驗命令，**單項失敗只記記錄並繼續，不中斷退出**。

機器重置後，拉取倉庫跑一次指令碼即可全部恢復。參考課程：[《Grok Bot 虛擬機器重置後工具全沒了？備份恢復課程（附提示詞）》](https://jcng5q8n0f3z.feishu.cn/wiki/Q6ZdwzjO5i6z0pkdMfyca8Cbnye)。

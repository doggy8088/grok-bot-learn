## 21.3 記憶管家：把 Bot 的核心記憶裝進私有倉庫

Grok 官方沒有全量匯出記憶的功能，帳號變更或系統遷移時，對話攢下的偏好全會丟掉。辦法是設立一個**記憶管家 Bot 備份到私有 Git 倉庫**，把記憶沉澱為純文字快照。

[《Grok Bot 百萬撤離：一套完善的 Agent 系統備份方案》](https://jcng5q8n0f3z.feishu.cn/wiki/W0TCwnTmbiIJ9KkF4S4cV6ifnCh)

### 記憶分層與管理原則

- **分層邏輯**：公共 Skill、外掛組態和雲端電腦本地文件歸共享層，全員可讀；單個 Bot 的 Description 規則契約、專屬獨立記憶和 Routine 任務歸專屬層。
- **管理原則**：動態業務事實只存源頭指標，用時回源抓取；共用記憶須經人工審核，防止交叉感染；固定操作流程固化進 Skill 程式碼。

[《4.6 虛擬機器、記憶與備份》](https://jcng5q8n0f3z.feishu.cn/wiki/KUggwkhqqiRyxZkwTLhcrCU2ncg)

### 倉庫結構與歸檔工作流

```text
├── bots/                     # 各 Bot 獨立組態與記憶
│   ├── cyber-xiaowan/        # 單個 Bot 資料夾
│   │   ├── agent-spec.md     # 身份設定、名稱、bot-id、slug、description
│   │   ├── MEMORY.md         # 核心記憶全量快照
│   │   ├── profile.md        # 角色資訊與權限邊界
│   │   └── archive/          # 歷史版本與過往記錄
│   └── ...                   # 其他 Bot 目錄
├── meta/                     # 全域Metadata與多 Bot 拓撲關係
├── shared-user-memory/       # 帳號級共享記憶
├── vm-services/              # 虛擬機器服務總帳與恢復指令碼（見 21.2 節）
├── README.md                 # 倉庫使用說明與最新狀態
├── RESTORE.md                # 跨環境恢復操作 SOP
└── registry.md               # 登記索引
```

Bot 目錄下的 `MEMORY.md` 提煉為身份權限、歷史決策和現場快照三層。管家按三步完成歸檔排程。
1. 枚舉當前帳號下的 Bot，圈定核心備份名單。
2. 下發標準化指令，讓各 Bot 讀取當前記憶並寫入 `/workspace` 對應的 Markdown 文件。
3. 掃描敏感資訊，**確認無明文 Token** 後統一打上日期標記（如 `tag-2026-10-15`）推送到遠端私有倉庫。

**Bot 負責全量快照，Git 負責增量追蹤**。Bot 每次直接全量覆蓋文件，版本變動交由 Git 沉澱。

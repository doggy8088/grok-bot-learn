## 多 Bot 文件交接約定與目錄規劃

### 基於文件的協作模式

**Bot 之間讀不到彼此的聊天記錄**，串聯協作全靠共享磁盤裡的文件交接。

開發者 0xlangeai 做推文畫像網站時跑通了四步協作，每個 Bot **只需在提示詞裡接收上一棒的文件路徑**。具體實踐見 [《4.6 虛擬機器、記憶與備份》](https://jcng5q8n0f3z.feishu.cn/wiki/KUggwkhqqiRyxZkwTLhcrCU2ncg)。

1. 整理員抓取內容，生成 `tweets.md`。
2. 分析師提煉 `tweets.md`，輸出 `profile.md`。
3. 設計師根據畫像生成 `design.md`。
4. 工程師讀取設計文件建構程式碼。

### 共享磁盤目錄規劃

建議建第一台機器起就定好目錄，避免多 Bot 把磁盤寫亂。

| 目錄路徑 | 存放內容 | 寫入規範 |
| --- | --- | --- |
| `/workspace/handoff/` | 多 Bot 中間產物 | 統一 Markdown 或 JSON，檔名帶任務前綴 |
| `/workspace/projects/` | 專案程式碼與資產 | 按項目劃分獨立子資料夾，關聯各自 Git 倉庫 |
| `/workspace/tools/` | 本地自寫指令碼工具 | 僅保留無密鑰原始碼，排查無誤後同步進備份倉 |
| `~/.env` 或本地文件 | 本地 API 密鑰 | **僅存機器本地**，嚴禁提交程式碼倉或在會話中打印 |

### 磁盤空間清理與 Disk Saver

空間不足時，系統會彈出 `Computer is low on disk space` 或 `Computer is critically low on disk space` 警告。

點選側邊欄 **Disk Saver** 的「Go to Disk Saver」可查看清理建議。**未經確認它絕不擅自刪除文件**，拒絕清理則原樣保留。
